### 1. Meta 全量部署 Catching JiTTests：LLM 在代码合入前按需锻造「一次性捕获测试」，H1 拦截 74 个严重隐私 bug、隐私 SEV 总量降 20%（Meta 官方工程博客 | 2026-10-29 UTC 16:00）

**事件概述**：
Meta 工程博客发布《Catching Bugs Before They Land》，首次系统披露 Catching JiTTests（即时捕获测试）从研究原型进入**全量生产基础设施**：每次 PR 提交时由 LLM 按需生成专攻「本次 diff 引入的行为差异」的一次性测试——默认不入库、用完即弃，工程师只回答「这个行为变化是否预期」的是非题。该体系的概念与论文（arXiv:2601.22832，《Just-in-Time Catching Test Generation at Meta》）于 2026 年 2 月公开，本条事件为 10-29 官方博客的生产规模部署详解（RSS pubDate Thu, 29 Oct 2026 16:00:12 GMT = 北京 10-30 00:00，落窗）。

**技术与工程价值**：
- **核心机制**：双管线并行生成——dodgy diff 管线把 diff 直接当「嫌疑变异体」，生成能区分 parent/diff 行为的测试（铺量、覆盖广、误报多）；intent-aware 管线先读 diff 标题/描述/代码推断变更意图与风险点（空值、边界、状态机），在 parent 上注入变异后生成「parent 过、mutant 挂」的测试再打真实 diff（精准）。同一测试 parent 过而 diff 挂记为 weak catch，经 RubFake 确定性规则评估器（识别布尔翻转、mock 错误、反射断裂等误报模式并附风险标记）+ 多模型 LLM-as-Judge 集成（输出 -1~+1 语义分、等级与理由并聚合排序）过滤假阳性，仅高分候选推给人审；passing 池经人工评审后有选择地「收割」为长期加固测试，实现「临时探针 + 永久资产」双轨。
- **实际影响**：直接回应 AI Coding 时代的结构性矛盾——agent 生成代码的变更速度已超过人类写测试与维护测试套件的速度，传统测试「守未来、不抓当下」且脆断维护成本爆炸。把测试变成按 diff 定制、阅后即焚的动态防线，人类审查负担被压到「一句是非题」量级，是头部机构把 LLM 测试生成推进到**全量 CI 基础设施**的标杆样本；对任何自建 agent 编码工作流的团队，RubFake 规则层 + judge 集成 + human-on-the-loop 的分层降噪设计可直接借鉴。

**关键指标/资源**：
- 评测/性能（均为 Meta 官方披露口径，自述数据，未见第三方复现）：589 名工程师实际参与（占触达范围 64%）；推送给人审的候选捕获真阳性率 60%；2026 上半年拦截 74 个严重隐私 bug，隐私类 SEV 总量同比下降 20%，且工程师交付速度未受拖累（论文期数据另含：22,126 条生成测试分析、intent 管线单 diff 捕获率 4.0%→7.9%）。
- 代码/论文：官方博客 https://engineering.fb.com/2026-10-29/security/catching-bugs-before-they-land-jittestings-human-on-the-loop-approach-at-full-scale/ ；方法论文 arXiv:2601.22832（2026-02）；未开源。

### 2. Figma 公开自研画布编辑模型训练方法：25 万合成样本 SFT 起步、确定性校验器 + 视觉评委做奖励，转向 RL 后内部评测 77.8%（Figma 官方博客 | 2026-10-29）

**事件概述**：
Figma 官方博客发布《How we're training a Figma-fluent editing model》，详解为 Figma Agent 训练**专用画布编辑模型**的完整配方：任务不是从零生成设计，而是对既有画布做「调间距、换颜色、按反馈重排」的小步编辑；先用 25 万+ 合成样本做 SFT（起始设计 + 合成编辑请求 + 成功改动三元组，以 Figma 原生文件格式表示、输出可直接落回画布），训练流水线中教师模型先尝试编辑、再由确定性校验器与视觉模型评委检查有效性并反馈自我修正；早期基于 Llama 3.3 70B 的版本在 25 万样本训练后，编辑任务表现已能与当时顶级模型竞争。官方渠道条目发布时刻 2026-10-29T21:00:02Z（北京 10-30 05:00，落窗；博客页仅给日期级 10-29，已列待核实）。

**关键指标/资源**：

### 4. Pika 开源 Pika-H3-Flex：MiniMax H3 后训练六步采样视频模型，LoRA 适配器 + Apache-2 推理包落地（Hugging Face 官方仓库 | 2026-10-29 UTC 17:08）

**事件概述**：
Pika Labs 发布并开源 **Pika-H3-Flex**——对 MiniMax H3（2026-07-31 开源的 33B 全模态音视频生成基座）做后训练的成果：HF 仓库 Pika-Labs/Pika-H3-Flex 创建于 2026-10-29T17:08:44Z（北京 10-30 01:08，落窗），官方博客/X 同日发布。核心卖点是把采样从 50 步蒸馏到 **6 步**、原生输出带 32kHz 立体声的 480p/768p 视频，官方称 15 秒 768p 片段仅需约 7 秒 DiT 计算（受控基准口径）。

**技术与工程价值**：
- **核心机制**：三阶段后训练——①自建美学筛选音视频语料 SFT（仍 50 步教师档）；②PDMD（Projected Distribution Matching Distillation）把采样 50→6 步（官方称标准 DMD 在其实验不稳定）；③蒸馏后奖励学习：ReFL（美学/清晰度）与 DPO（指令遵循/真实感）分别训练 LoRA 再合并为单一适配器、不增推理步数。交付为 FL2VA（文本+首/尾帧）与 Ref2VA（多模态引用：最多 9 图 + 3 视频 + 3 音频共 12 个引用文件，支持运动迁移、角色替换、引用引导编辑）两个 LoRA（各 ~2.77GB FP32），叠加 H3 基座（组件合计约 210GB）；推理代码 Apache 2.0 上 GitHub，ComfyUI 官方当日提供三个模板工作流（ManualSigmas 1000/750/500/250/100/40/0、video shift 12 / audio shift 3、CFG 1.0）。8×B300 上经 fused kernels / FlashAttention-4 / 块稀疏注意力的服务栈优化，5 秒 768p 完整推理 3.409s→2.129s（1.60×）。
- **实际影响**：这是继 fal H3 Max（09-01，闭源 API 路线）之后第二个 MiniMax H3 后训练产品，但选择了开源分发——把「视频模型迭代成本」压到 LoRA 级别，创作者可在本地以 6 步调度做草稿级快速迭代（单卡实测 5 秒 1344×768 约 1 分钟，与官方 7 秒口径差距须注意：后者为 8×B300 受控基准的 DiT 计算时间、非端到端延迟）；「开源适配层 + 闭源高级能力（4K 上采样器、五条可编辑音轨分离留在云端）」的分层开源模式，与 Mistral 的 MaaS 商用墙（第 118 跑）同属最新开放策略样本。

**关键指标/资源**：
- 评测/性能（均为 Pika 自述，未见第三方复现）：采样 50→6 步；15s 768p 约 7s DiT 计算；5s 768p 完整推理 3.409→2.129s（1.60×，8×B300）；平均较 fal H3 Max 快 1.8×；内部五项视觉/音频质量指标最高（视频技术质量 12.3 vs H3 基座 11.7 / fal H3 Max 10.6；音视频对齐与文本-视频对齐与对手持平略弱）；盲测人偏好在解剖结构、复杂构图、音画同步、引用任务的视觉风格/构图/相机运动领先，物理表现、多场景叙事、光照材质、动作密集引用仍落后；自述 DesignArena T2V 开源权重第一、总榜第 7（发布日榜单页未确认，launch 博客残留 "Editorial checks – remove before publishing" 草稿块，已列待核实）；价格自述 768p 首发 $0.01–0.02/秒。
