01 · AI Coding / Agent 架构

DeepSeek 发布 Super-agent 架构并开源 dsh-superagent-prototype：Router 常驻分派 + Worker 隔离并发，任务完成 P95 15.7 分钟对单 Session 29.5 分钟

GitHub deepseek-ai/dsh-superagent-prototype + DeepSeek Harness 团队文章 | 2026-10-31 BJ 17:32:46 建仓 / 20:05:39 首发提交

DeepSeek Harness 团队发布《Super-agent 设计探索：迈向更自主的 Agent 系统》（Exploring Super-agent Design: Towards a More Autonomous Agent System），把 Agent 从「用户手动开的单次会话」解绑为跨信道常驻、可并行推进多任务的连续实体：上层 Router 承接交互、维护全局上下文并分派任务，下层 Worker 在相互隔离的会话中并发执行、只向 Router 汇报而不直接对用户说话。同步以 MIT 协议开源研究原型 dsh-superagent-prototype——面向单个 GitHub 仓库的 proactive coding agent，监听 GitHub（可选飞书），在独立会话与工作目录中干活并以 Pull Request 交付。一手时点：仓库 created_at 2026-10-31T09:32:46Z（北京 17:32:46），首发提交 feat: add the dsh-superagent research prototype 于 12:05:39Z（北京 20:05:39），检查时 star 325。

技术与工程价值

  • 五模块撑四特征：① 双层架构——Router 只做全局序点/协调/记忆，可用轻量模型甚至省掉 Bash；Worker 决定结果与代码质量，配最强模型 + 全套工具，内部可再开 Subagent 或本身就是一个 Agent Team，对上层透明。② 事件驱动——群聊、邮件日程、代码评审评论、CI 结果统称 Trigger，先经程序层 Fast Path（来源/群组/白名单）过滤，再交语义层 Slow Path 判断；同一话题或同一 PR 的连续事件构成 Thread，Worker 直接订阅 Thread，后续事件绕开 Router 直达（多对多订阅，两个 Worker 改同一 PR 时互见提交、自行解冲突）。
  • 把上下文窗口当 Cache 管：Inline & Spill（近期信息内联、超预算内容留在窗口外只留引用或摘要，长内容先给前 50 字并留「续读」入口）＋ 链式召回 Chain of Recall（Trigger/Thread/Worker Session 各配唯一 ID，沿引用图逐跳找回旧任务）；再叠加投机执行——群里讨论 Bug 时后台先复现找修复，只有确认问题且找到简单修法才交付，否则全程安静。
  • 全双工与一直在线：耗时工具调用改成异步 start()/stop() 构成异步 ReAct Loop（已在 DeepSeek Harness 实现但未默认开启），IM 信道单次回复限 100 词、PR/邮件信道写结构化交付；借存算分离把 Agent Loop 放云端无状态容器、会话状态进数据库，执行环境留在原地由端侧轻量 daemon 承接命令，支持 BYOM 且设备重新上线后自动续跑；另设独立 Watchdog Session 作外部控制回路，既查基础设施故障，也用模型判断 Worker 是否原地打转或偏离目标。
  • 实际影响：把「一个人同时能跟几个 Agent」从注意力问题（官方观察通常 3–5 个活跃 Session）转为系统调度问题，同一套骨架同时覆盖研发协作与个人助手。官方自列未解问题：Router 水平切分粒度与层内拓扑、跨月长程记忆、脱离 Session 的中途接管、实例间 A2A，以及安全隐私——云端 Agent Loop 若因服务端入侵或提示词注入失守，连着的端侧设备（未提交改动、私有凭据、内网服务）都有被控制风险。团队亦坦言思路来自计算机系统经典工程思想而非全新理论。
  • 读代码前须知：README 明示「研究原型、非正式产品；大量工程由 coding agent 完成，可能含 bug、风格不一致」，且已为公开做改编、与内部实现不等同，文中部分设计属未来方向未实现；安装流程本身设计为交给编码 Agent 执行。

OpenCode 启动「Operation Cheepseek」第四阶段：10 美元 OpenCode Go 订阅给到 100 美元 DeepSeek V4.1 Flash 额度，订阅杠杆升至 10 倍

OpenCode 官方 X | 2026-10-31 日期级（IT之家 14:40 BJ 首发转述）

AI 编程工具 OpenCode 于 10 月 31 日在 X 宣布 Operation Cheepseek 第四阶段：面向 10 美元/月的 OpenCode Go 订阅，把内含的 DeepSeek V4.1 Flash 用量额度提升至价值 100 美元（约 667 元人民币）。计划四级演进：30 美元 → 60 美元（原限时额度转永久）→ 80 美元（配合 OpenCode 达成 10 万 GitHub Stars、取消峰谷限制）→ 100 美元。

技术与工程价值

  • 杠杆建立在模型成本结构上：DeepSeek V4.1 Flash 为 9 月发布的原生多模态 MoE，总参数 552B，输入侧每 token 激活约 8B、输出侧约 16B，最高约 100 万 token 上下文，支持文本与图像输入、函数调用与智能体工作流；官方另称其 KV Cache 对 HBM 需求降至上一代四分之一、对 SSD 需求降至八分之一（厂商自述，未见第三方复现）。低激活比 + 长上下文 + KV Cache 显存需求下降，正是长上下文 agent 任务单价下降的来源。
  • 实际影响：编码 Agent 的「订阅经济学」继续加码——同订阅可完成更多代码生成、审查、文档理解与多轮工具调用/长文档分析；对以 token 计价的其他 harness 形成价格锚定压力。第三阶段已取消峰谷限制，第四阶段等于把低价长任务的边际成本压到订阅价之下。
  • 口径注意：100 美元额度不等同现金余额，按模型调用计费折算使用价值；实际可用量仍受请求频率、上下文长度、输入输出规模与平台速率限制影响。
