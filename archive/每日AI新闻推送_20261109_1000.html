事件概述

Simon Willison 发布博客《parse_number() as a SQLite extension: C vs Rust》：遛狗时起意尝试编写 SQLite C 扩展，用 Claude 聊天（Opus 5.5）实现 parse_number()（将 -$1,234.56、12.5% 等格式化字符串转为可求和/排序的数值），随后横向对比同一功能的 C 与 Rust 实现，并把全程整理为研究报告发布于 simonw/research 仓库。

技术与工程价值

  • 核心机制：同一功能三路实现基准对比——初版 Rust 二进制 298–321 KB vs C 14 KB；Rust 版反而运行更快，遂再让 Claude 写优化版 C 解析器；最终优化 C 在混合数据上达 19 ns/row，其余实现 46–67 ns。完整呈现「LLM 对话式原型 → 基准驱动迭代 → 报告留档」的单人工程闭环。
  • 实际影响：单人凭聊天模型一次会话完成带基准对比的原生扩展工程全流程，再次验证「Claude 单会话 = 小型原生工程任务」的现实上限；simonw/research 的报告范式（问题动机 → 多实现对比 → 基准数字 → 结论）可作为可复用模板。

关键指标/资源

  • 评测/性能：C 扩展 14 KB vs Rust 298–321 KB；优化 C 19 ns/row vs 46–67 ns（作者自测口径，未见第三方复现）
