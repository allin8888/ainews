### 1. Runway 发布 Praxis-1 开放权重世界动作模型：视频预训练直接驱动真机操控，10 月内公开权重（Runway 官方研究帖 | 2026-09 底发布，10/1 集中报道）

**事件概述**：
Runway 宣布其首个开放权重世界动作模型（World Action Model, WAM）**Praxis-1**，基于与通用世界模型（Solaris、GWM Worlds 2）同源的大规模视频预训练，目标是让机器人策略无需依赖昂贵的遥操作数据采集。模型正与 Noble Machines、Standard Bots、Ultra 三家合作伙伴在真实硬件上测试，公开权重预计在数月内发布。

**技术与工程价值**：
- **核心机制**：Praxis-1 将视频预训练中学到的物理直觉（物体行为、手部运动、任务中途状态）直接迁移为机器人控制策略。Runway 声称在自有世界模型中模拟机器人策略与真实世界性能的相关系数达 **0.95**，可替代成本更高的 3D 重建方法。对比实验中，web 视频预训练与遥操作视频预训练微调后放置误差分别为 16.1 cm 与 16.0 cm（Runway 自认统计不显著），验证了视频作为替代数据源的可行性。
- **实际影响**：这是世界模型从「数字世界生成」走向「物理世界操控」的关键一步。视频数据的无限可扩展性直接解决具身智能最核心的数据瓶颈——遥操作数据采集成本高昂且规模有限。开放权重策略意味着机器人硬件开发者可以在本地部署与自定义，不受闭源 API 锁定。

**关键指标/资源**：
- 评测/性能：web 视频 vs 遥操作视频预训练：16.1 cm vs 16.0 cm 放置误差（93 对评估，Runway 自述统计不显著）；Sim-to-Real 相关系数 0.95（**Runway 自述数据，未见第三方独立复现，待核实**）
- 代码/论文：Runway 官方研究帖（runway.com/research/introducing-praxis-1）；公开权重预计 2026 年内发布；早期合作伙伴：Noble Machines（双臂操作）、Standard Bots（RO1 六轴臂）、Ultra（移动平台）
- 来源：https://runway.com/research/introducing-praxis-1

### 2. AWS 开源 Strands Decider 2B：2B 参数决策模型替代 LLM 做 Agent 工作流路由，全量代码与权重开放（AWS Strands Labs / TechCrunch | 2026-10-01 美东）

**事件概述**：
AWS 通过 Strands Labs 开源了 **Strands Decider 2B**——一个 20 亿参数的决策模型（Decision Model），专为 Agent 工作流中的「从预定义选项中选择下一步」设计，替代通用 LLM 在每个工作流步骤都调用大模型的高成本模式。基于 Qwen3.5-2B 的「躯干」（去掉文本生成头，换为约 100 万参数的指针头 + rank-16 LoRA 适配器），支持本地 CPU/GPU 运行，RTX 3090 中位延迟约 115ms、M3 MacBook 约 153ms。

**技术与工程价值**：
- **核心机制**：项目起源为 AWS 杰出工程师 Marc Brooker 在 TypeSafe 发布 Jev（15-16 秒前出隐身，融资 $40M）后三周内复现的自制模型——该原型曾短暂登顶 JevBench 2B 级排名，随后被 Strands Labs 团队工程化为正式开源产品。输出为**校准置信度分数**而非自由文本，Agent 编排器可据此决定继续、澄清或转交。JevBench 上在 33 个 2B 级模型中排第三（排除略大模型后为 30 个中第一），easy tier 准确率 100%。
- **实际影响**：「决策模型」是一个仅诞生三周的新模型类别，已有数十个独立实现（OpenAI 同期推出闭源 Decisions API）。Agent 编排层最痛的成本问题——每个工作流步骤都调用完整 LLM——被此路径直接压缩：简单决策步骤的成本从 LLM token 计费降至接近零（本地运行），且置信度分数为多 Agent 架构提供了可审计的「信任阈值」信号。AWS 明确声明该模型不适用于编码、聊天、摘要等需要自由文本生成的任务。

**关键指标/资源**：
- 评测/性能：JevBench 2B 级第三（33 模型中）；easy tier 100%；RTX 3090 中位延迟 ~115ms；M3 MacBook ~153ms；**基于 Qwen3.5-2B 基座**
- 代码/论文：权重 + 训练数据 + 训练脚本全量开放（GitHub / Hugging Face）；v19 快速迭代循环完整 changelog 随仓库发布
- 来源：https://techcrunch.com/2026/10/01/amazon-releases-its-own-jev-clone-as-decision-models-flood-the-web/

**标签**：`#Agent 基础设施` `#决策模型` `#开源` `#工作流编排`

### 3. AIDE² 论文：AI 研究智能体 8 天自主运行递归改写自身代码，7 次连续增益覆盖 4 个外部基准（AGI Hunt | 2026-10-02 报道，arXiv 首发时刻待核实）

**事件概述**：
新论文《Recursive Self-Improvement of AI Research Agents》报告了 **AIDE²** 的真实递归自我改进（RSI）实证：智能体将其自身源代码作为编辑对象，提出修改→构建新自身→在 AI R&D 任务上运行→保留在隐藏评估中得分最高的版本。被接受的改写成为下一轮编辑的执行者——真正的「递归」而非固定程序编辑他人代码。一次 **8 天无人干预运行**中，系统发现 7 次连续增益，涵盖新搜索策略到自身上下文压缩与记忆机制。

**技术与工程价值**：
- **核心机制**：与 MetaRSI-v1（第 62 跑，9/14）的「元递归架构」不同，AIDE² 的递归在于**编辑对象与执行者为同一系统**——每轮改进后的 Agent 直接成为下一轮的编辑者，形成自指闭环。外层（meta）循环锁定评价标准防止 Reward Hacking，内层（task）循环在 AI 研发任务上实测增益。
- **实际影响**：增益在四个 held-out 基准（ML 工程、启发式算法工程、物理天气预报）上保持稳定，说明递归改写并非过拟合到单一任务。这是 RSI 从「有界闭环」（第 61 跑 Dario Amodei《We Must Pace the Frontier》呼吁治理的对象）向「递归增益」第三层（「点火」）迈进的关键实证——但 8 天 7 次增益的时间尺度远未证明复利加速，仅证明方向可行。
- **待核实**：arXiv 原始提交时间戳未在窗口检索中直接确认（AGI Hunt 10/2 为首见公开报道），需补充 arXiv 编号与 v1 提交日。

**关键指标/资源**：
- 评测/性能：8 天运行 7 次连续增益；4 个 held-out 基准（ML 工程 / 启发式算法 / 天气预报）增益保持稳定（**具体数值未在公开报道中列出，待核实**）
- 代码/论文：论文标题《Recursive Self-Improvement of AI Research Agents》；AGI Hunt 10/2 报道（agihunt.info/en/p/1a0f83ec5473d7a76e6e515e96e）
- 来源：https://agihunt.info/en/p/1a0f83ec5473d7a76e6e515e96e

### 4. Benzi 编译器驱动编码 Agent：不读源码而用编译器静态分析，SWE-bench Verified 78.2% 且单 fix 成本 <10 美分（AGI Hunt | 2026-10-02 报道）

**事件概述**：
开发者发布 **Benzi**——一种以编译器与静态分析（而非读取源码片段或构建 embedding）为核心机制的编码 Agent。在编辑前，编译器报告「爆炸半径」（blast radius）并执行完整静态检查，模型因此无需频繁询问「这个函数的输入来源」。核心假设：对仓库的**索引**优于读取原始代码，比业界上下文窗口军备竞赛更经济。

**技术与工程价值**：
- **核心机制**：三层「真相分级」（truth tiers）——① 静态可分析事实（编译器直接给出）；② 静态不可分析但可运行时追踪事实（runtime tracer 桥接）；③ 需要模型推理的事实。语法与语义验证写入（writes）确保每次编辑通过编译；上下文感知的模型自写复现脚本（model-written repros）支持多文件重构；任务中途支持模型热升级（mid-task model upgrades）。支持 Python、JS/TS、Java、C#、C++、C、Go、Rust、Ruby。
- **实际影响**：与 Claude Code（读 20,704 行）、DeepSeek harness（读 43,598 行）对比，Benzi Sonnet 仅读 **9,125 行**即完成相同任务。SWE-bench Verified 78.2%（使用 V4flash）在 <10 美分/fix 的成本下达到，验证了「确定性编译器信号替代 token 密集的源码读取」路线的工程可行性。OpenCode（读 65K+ 行）因重复失败被排除。
- **待核实**：78.2% 为发布方自述基准，未见第三方复现；单 fix <10 美分使用 V4flash 模型，未公开 V4flash 的具体定价结构。

**关键指标/资源**：
- 评测/性能：SWE-bench Verified 78.2%（V4flash 驱动）；读取行数 9,125 vs Claude Code 20,704 / DeepSeek 43,598 / OpenCode 65K+；<10 美分/fix（**发布方自述，未见第三方复现，待核实**）
- 代码/论文：AGI Hunt 10/2 报道（agihunt.info/en/p/1a0f96ff47f5db7d1615d84f370）
- 来源：https://agihunt.info/en/p/1a0f96ff47f5db7d1615d84f370

### 5. 蚂蚁集团 × 北大 × 澳门大学 Marathoner：Qwen3.5-9B 长时程编码 Agent 10+ 小时连续运行，SWE-bench Verified 77.5%（arXiv:2609.34378 | 2026-10-02 AGI Hunt 报道）

**事件概述**：
蚂蚁集团、北京大学与澳门大学联合发布 **Marathoner**——基于 Qwen3.5-9B 的长时程（ultra-long-horizon）软件工作后训练管线。从 10,000 个 GitHub 仓库的 100,000 个重大版本 PR 中挖掘软件任务，通过多任务链接（Multi-Task Chaining）将 5 个任务组合为接近前沿规模的持续工作负载（执行上限 40 小时），并使用 Kimi K3 成功运行轨迹作为训练信号、在真实执行环境中进行 RL 训练。核心创新是**奖励晚段进展**（late-stage progress bonus）——即使任务尚未完成，发现隐藏 bug 等有效进步也会获得正奖励。

**技术与工程价值**：
- **核心机制**：Marathoner 将 9B 小模型的 SWE-bench Verified 从基座 43.8% 提升至 **77.5%**，Terminal-Bench 2.0 从 27.3% 提升至 **57.2%**。在 FrontierSWE 与 SWE-Marathon 上超过 Gemini-3.1-Pro。10+ 小时连续编码、1000+ 工具调用的耐力数据，展示了「持久性可被训练进小模型」的可行性。
- **实际影响**：这是一个明确的「小模型 + 长时程 RL」路线验证——不依赖 2.8T 参数开放权重模型（如 Kimi K3）也能达到接近前沿的编码结果，且成本结构对本地部署/边缘计算场景极具吸引力。但权重、训练代码与数据集均未公开（AGI Hunt 报道确认），实际复现门槛较高。
- **待核实**：权重未公开，无法独立验证 77.5% 基准；10+ 小时数据来自高难度子集（FrontierSWE 平均 3.56 小时 / 648 工具调用），非全部运行。

**关键指标/资源**：
- 评测/性能：SWE-bench Verified 43.8% → 77.5%；Terminal-Bench 2.0 27.3% → 57.2%；FrontierSWE / SWE-Marathon 超 Gemini-3.1-Pro（**发布方自述，未见第三方复现，待核实**）
- 代码/论文：arXiv:2609.34378；AGI Hunt 10/2 报道（agihunt.info/en/p/1a0f79f8e898ca6f6a9d0f9cb51）
- 来源：https://arxiv.org/abs/2609.34378
