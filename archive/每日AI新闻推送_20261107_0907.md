### 1. OpenRouter 重建 Auto Router 并首推编码专用 Auto Code：11 因子选模，每任务成本较 Claude Opus 5.5 低 74%（OpenRouter 官方博客 / 官方 X | 2026-11-06）

**事件概述**：
OpenRouter 发布下一代 Auto Router（`openrouter/auto`），并首次把编码场景单独拆出 `openrouter/auto-code`。新引擎不再依赖「任务类型」等少量粗粒度信号，而是对每次请求评估 11 个因子，叠加实时定价、provider 健康度与缓存状态，从 600+ 模型与可选推理力度中决定模型；官方 X 主帖落在窗内 `2026-11-06 16:19Z`（BJ 11-07 00:19）。同时披露 10 月平台数据：790T token、Agent 消耗 76% 平台 token。

**技术与工程价值**：
- **核心机制**：① 明确区分 model routing（为请求选模型）与 provider routing（为模型选托管方，按偏好/uptime/延迟/价格/缓存可用性）。② 路由可作用于任意模型集合，同时遵守 guardrails、零数据留存、provider 限制、允许/排除模型列表与 BYOK；模型与 provider 的解耦让治理策略先于性能生效。③ Auto Code 针对 coding harness 单独调参：从更高编码模型档位起步、更重速度权重、更严惩罚失败、**克制切换以保住 prompt cache**（beta 中近九成 agent turn 保持同一模型），并对「同一错误反复出现 / 编辑后测试失败」等信号提高切换概率。④ chatroom 提供路由决策解释面板，API 可通过 router metadata 拿到同一分析；模型页展示按 session 类型划分的选模分布及随难度上移的迁移。
- **实际影响**：把「模型选择」从开发者手工维护的静态配置变成随价格、健康度、缓存状态与失败信号在线更新的基础设施层；Auto Code 把编码 Agent 的延迟与一次通过率纳入目标函数，而非只最小化单价。官方同时坦承路由器不能在成本-质量曲线上稳定击败最强单一前沿模型，买到的是长期成本与表现的一致性；已明确知道目标模型的用户仍应直接指定模型。路由不额外收费，按实际服务模型计费。

**关键指标/资源**：
- 评测/性能：相对上一代路由器基准最高 4× 提升；路由步骤 p90 延迟 0.65 s 对 1.96 s（约 3×）；Auto Code 在官方 5 项基准上得分与 Claude Opus 5.5 相当、每任务成本低 74%；beta 中无效工具调用降 4×、被截断的 agentic 响应减半；月处理 2.5T token、覆盖 10 万+ 用户；10 月 790T token、Agent 占 76%（约 600T）、缓存命中率 90%、每 token 有效价较 1 月降 57%–70%。官方基准表细项：DeepSWE 69.0%/$0.57（Auto）→ 74.3%/$1.98（Auto Code），旧 Auto 64.6%/$1.37；TerminalBench 4.0 45.7% → 50.0%，旧 28.3%；Auto Code 在 4/5 分数上超 Auto，但 Tau-bench Banking 52.6% 略低于 Auto 53.1%，且 4/5 任务成本高于 Auto（TerminalBench 达 3.7×）。**以上均为 OpenRouter 自家基准与内测数据，未见独立第三方复现；74% 仅是相对 Opus 5.5 的每任务成本，不是每 token 降价**。
- 代码/论文：https://openrouter.ai/blog/announcements/auto-and-auto-code-routers/ （模型入口 `openrouter/auto`、`openrouter/auto-code`；Auto Code 暂不支持 EU in-region routing）

### 2. Ai2 开源 ToyBlocks / FoundationWorlds：受控机器人学习世界，85,336 条长时演示 + Agent 自写技能描述把成功率从 24% 抬到 63%（Hugging Face 社区博客 / GitHub allenai | 2026-11-06）

**事件概述**：
艾伦人工智能研究院发布 FoundationWorlds 框架的首个「受控世界」ToyBlocks：一张桌面、一条仿真机械臂与带字母/图案的积木，配套自动生成的演示数据、两个已训练模型与评测工具，目标不是刷榜而是让机器人学习的**失败可复现、可归因**。首发落在 Hugging Face 社区博客 `2026-11-06 14:00Z`（BJ 22:00），窗内。全栈开源：主代码 Apache-2.0、数据集 ODC-BY、模型卡公开。

**技术与工程价值**：
- **核心机制**：① 免遥操作数据生成——在 NVIDIA Isaac Lab 里用 RL 与运动规划产出短技能，可用 privileged simulator state（精确位姿）替代相机估计；task-and-motion planner 选排技能生成带标签演示，单 GPU 上数百 plan 并发、最高 24× 实时。② 可实验控制——目标写成 PDDL 规划规约，评测系统据此给完成度与中间进度打分；演示存 LeRobot 格式，研究者可对训练混合按技能加权、在留出任务上评测，把数据生成器变成实验自变量而非单纯堆数据。③ 层次策略可拆——Molmo2-4B-tb（约 45 亿参数）由前视相机图与文本目标产出短计划/下一动作/目标点，ManiFlow-tb（3.225 亿参数）由前视+夹爪图、机器人状态、任务信息与目标热图产出 action chunks；任一层可换成 oracle，从而把「坏决策」与「动作执行失误」分开；失败状态可回流数据生成补恢复演示。
- **实际影响**：空间外推实验（Stack/Unstack/Flip/Rotate）显示 ManiFlow、π0.5、MolmoAct 2 尽管经过大规模预训练，泛化依然很差——明确提示动作模型泛化远未解决。更值得关注的是自我修正闭环：让 Agent 试探意外技能行为并**自己重写技能描述**，成功率从默认描述的 24% 升到 63%，高于人类专家撰写描述的 36%；这是 RSI 焦点在「技能/提示资产层」可复用的落地形态，不依赖改权重。世界模型侧，Wan 2.2 在位姿与成功预测上领先，配合 100 次模型 rollout 的规划把未见区域策略成功率从 19% 提到 78%（该组数字仅见二级来源，待核实）。纯仿真数据训练、零真实样本直接在 Franka FR3 + Robotiq 上零样本运行，构成一次带明确边界披露的 Sim2Real 验证。

**关键指标/资源**：
- 评测/性能：85,336 条长时演示（每条约 6–12 个技能演示）、近 1,600 小时执行、1.44 亿帧；单 GPU 数据生成最高 24× 实时；Agent 自写技能描述 24% → 63%，人类专家 36%，默认 24%；基于 Claude Opus 5.5 的系统解 30/30 经典积木任务，search-and-spell 场景 63% 正确求解或正确判不可行（形近字母混淆 13%、字母方向错误 15%）；ManiFlow 原子技能仿真 80.0% / 真机 81.1%；层次系统仿真 55.5%（111/200）/ 真机 50.0%（15/30）。**均为 Ai2 自述，未见独立第三方复现**；真实机层次评测使用最简单配置（字符可见且正立）、仅 30 个场景，ManiFlow 卡记录同一 128 仿真 episode 四次运行成功率在 54%–59% 间波动（仿真与批量推理非逐位确定性），统计置信度不足。
- 代码/论文：https://huggingface.co/blog/allenai/toyblocks · https://github.com/allenai/ToyBlocks · https://huggingface.co/datasets/allenai/toyblocks-data · https://huggingface.co/allenai/Molmo2-4B-tb · https://huggingface.co/allenai/maniflow-tb

### 3. Amp 推出 Spaces：主 Agent 自主拆解目标、创建并协调并行 Agent 线程（Amp 官方 ampcode.com/news/spaces | 2026-11-06）

**事件概述**：
AI 编程工具 Amp 上线 spaces：一个 Space 是用户与**单个 Agent** 的对话，该 Agent 的职责是替用户 spawn 并协调其他 Agent 线程。用户不再手动创建、命名、追踪线程；官方页面标注 November 6, 2026，窗内中文媒体首发记录为 `2026-11-06 23:02Z`（BJ 11-07 07:02）。

**技术与工程价值**：
- **核心机制**：① 把「任务分解 + 线程创建 + 进度组织 + 结果汇总」这一层从人移到 Agent，用户只描述目标，Space 内主 Agent 生成并行线程并把进展以实时卡片呈现在聊天里，点卡片可进入对应线程查看产出、继续迭代或推进交付。② 团队共享同一 Space：成员可在同一聊天提需求、反馈、补充想法，任务卡显示当前状态与是否需要人工介入；评论默认不被读取，**只有被 `@amp` 提及时才进入 Agent 上下文**，用于抑制群聊噪声与越权指令。③ 官方三个自身案例：Spaces 功能本身在名为 "Spaces v1" 的 Space 中构建，团队把反馈/bug/新想法丢进聊天由 Agent 派发为线程；一次安全审查首次运行把代码库拆成 **16 个区域**、每区独立线程、每个 finding 再交另一线程交叉核验、汇总成 Space 内持续跟踪的文档；一次 service accounts 上线由单个 Space 完成灰度、监控 X/Slack/缺陷报告、修复线上 bug 与后续一周的系统健康监测。
- **实际影响**：与本期 OpenRouter 的「选模层」、GitHub 的「四阶段流程层」一起，构成同一窗口内 AI Coding 编排层的三条不同切法——Amp 把编排粒度抬到「目标级」，开发者角色从逐条调度 Agent 转向定义目标、审查结果与处理关键决策。这是产品形态层面的架构变化，但**官方未给出吞吐量、成功率、成本任何量化基准，也未开源**；仅凭 Amp 自身团队用法不能推断跨团队可迁移性。二级来源引用的「多 Agent 团队成本可升 5.1× 而质量几乎不动」提示协调成本不会因界面抽象而消失（待核实）。

**关键指标/资源**：
- 评测/性能：安全审查首次运行拆分 16 个代码区域并逐区独立线程复核；官方给出 3 个自身实践场景（功能共建 / 上线与支持 / 定期安全审查）；**无公开基准、无量化成功率、无开源代码**，16 区域为单一案例的定性规模。

### 4. Anthropic《The components of agent memory》：用「做梦」离线整理跨会话记忆，形成自我纠错的学习闭环（Anthropic 官方研究页 / 官方 X | 2026-11-06）

**事件概述**：
Anthropic 发布研究文章，系统拆解 Claude 智能体的记忆构成，并把「dreaming」定义为在两次交互之间的空闲期回放会话日志、修正错误、生成新表示、决定未来会话预加载什么。官方 X `@AnthropicAI` 于 `2026-11-06 21:16Z`（BJ 05:16）公告该工程博客。研究明确划定边界：agent memory 指从经验获得、跨会话保留、存于外部存储供后续读取的知识，**不含权重改变、单轮 in-context learning 与 compaction 摘要**。

**技术与工程价值**：
- **核心机制**：① 借人脑海马体—皮层分工做「即时捕获 / 离线巩固」两段式：会话中标记 salient 事件或写 memory notes，空闲期由 dreaming 纠错、建笔记、构建 Wiki 式关联表示、筛选高价值记忆预加载；源头思路来自 Letta / UC Berkeley 的 sleep-time compute。② 把「记忆是对未来的预测」写成设计原则——写下一条已验证规则即预测未来会话会复用它，因此写入时要判断显著性，预加载又要严控体量（过量占 token 且降低指令遵循）。③ 用 CL-Bench 1.0 数据库问答观察「失败—反思—验证—总结规则」闭环是否形成：每题从全新会话开始、只可读取持久记忆目录；Sonnet 4.6 只留下散落着未检验猜测的文件，Opus 4.7 汇总成单一参考文档并标注已核验/未确认，Sonnet 5 在判分后标记确认并写纠正，**Opus 5 首次闭合学习闭环**（每条含规则、规则为真的依据、历史答案与踩过的陷阱警告）。
- **实际影响**：把 RSI 从「改模型权重」下放到「改记忆与规则资产」这一可在生产环境迭代的层面，与本期 ToyBlocks 的「Agent 自写技能描述」、GitHub 的「Copilot Dreaming 提议 instruction/skill 更新」构成同一条技术线：三家在同一窗口分别把自我改进落到了技能描述、记忆笔记与流程规范三类可审计资产上。研究同时给出反直觉结论——记忆**少而精**优于堆砌，以及 dreaming 的纠错价值（比照原始会话记录修正记错的地点/事实后，任务从反复折返变为可达）。

**关键指标/资源**：
- 评测/性能：CL-Bench 数据库任务，Opus 5.5 用记忆 0.838 对无记忆基线 0.655，Sonnet 5.5 用记忆 0.833 对 0.644；《宝可梦红》中 Claude Fable 5 仅维护 10 个记忆文件得 4 枚徽章，Sonnet 3.7 写 413 个文件仅 1 枚徽章；约 35 万份企业文档上，dreaming 规模从 2 次会话扩到 128 次，25 个问题的达标率 13% → 48%。**上述量化数字经中文二级媒体转述官方研究，本报告未逐项核对 Anthropic 原文图表；全部为 Anthropic 自家实验，未见独立第三方复现**。
- 代码/论文：https://www.anthropic.com/research/components-of-agent-memory

### 5. GitHub《Beyond code generation》：单周 12 亿 commit 与 PR 评审耗时 +441% 的诊断，提出 Plan–Build–Verify–Observe 四阶段智能体工程（GitHub Blog | 2026-11-06）

**事件概述**：
GitHub 官方博客（作者 Nick Liffen，Nov 6, 2026；GitHub Blog RSS 窗内记录 `2026-11-06 22:15Z`＝BJ 06:15）用两组数据点出 AI Coding 的结构性错位：2026 年 10 月 GitHub 单周收到超 12 亿次 commit、同比多 400%+、超过 2025 全年总量；但 Faros AI 研究发现团队从低 AI 采用走向高 AI 采用时，PR 在评审环节停留的时间延长 441%。结论是「写代码变快了，围绕代码的工作没变快」。

**技术与工程价值**：
- **核心机制**：把研发流程拆成 Plan / Build / Verify / Observe 四阶段并逐段给出 Agent 落点。① Plan：Copilot 在 Slack/Teams 汇总分散上下文、生成带验收标准的 GitHub Issues，GitHub Agentic Workflows 自动打标签与估复杂度、低复杂任务直接派发，Plan Mode 先审计划再实施。② Build：Session continuity 跨客户端续接同一会话、云端沙箱执行（合盖后任务继续）、Copilot app 为各会话提供隔离仓库副本避免多任务互相污染工作树、repository instructions + shared memory 沉淀项目约定、**Copilot Dreaming** 回顾会话与 PR 反馈维护记忆并主动提议 instruction/skill 更新、Copilot Fusion 按任务选模型与推理深度、企业策略跨端生效。③ Verify：npm package firewall（public preview）阻断违反安全策略的依赖下载、Agentic Autofix 提修复、Agent Merge 处理失败检查/评审意见/合并冲突并可配置验证通过后自动合并（官方建议先从低风险仓库开始、先定义「哪些检查算足够」）。④ Observe：把 Copilot 接到可观测与业务数据（如 Fabric）定位受影响请求与客户群，起草带证据、验收标准与回归测试的 issue，Dreaming 再把事故教训写回记忆/技能/评审指引，闭合回 Plan。
- **实际影响**：把优化目标从「生成速度」显式转移到「评审、验证、上线后反馈」的吞吐与可治理性，并给出可量化的落地起点——从手上一项任务问四个问题（需要什么上下文、如何评审与测试、上线后如何知道有效、本周摩擦在哪），先在一个阶段放 Agent，再测评审是否变短、事故是否更易诊断。与本期 Amp Spaces（目标级编排）、OpenRouter Auto Code（选模层）共同说明：竞争重心继续从模型能力下沉到 harness / 流程 / 接入层。注意文中部分能力仍处 preview，且评审者仍须负责「代码是否实现了意图、可能出什么问题」这一不可替代的判断。
