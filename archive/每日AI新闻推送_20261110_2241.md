## 头部重点

- **把生成与验收分开**：AlphaProof Code 用多智能体生成证明，再由 Lean 内核与规格比对工具验收；验证对象是特定编译后的 libsignal，不是整款 Signal 应用“绝对安全”。见第 1 条。

## AI Coding · 可检查的多智能体研究

### 1. AlphaProof Code：多智能体把 Signal 安全性质验证到 AArch64 机器码（Google DeepMind）

**第一信源**：[官方发布](https://deepmind.google/blog/introducing-alphaproof-code/)；[技术论文与验证产物](https://google-deepmind.github.io/code-verification)；[官方代码仓库](https://github.com/google-deepmind/code-verification)。

**首发时间**：2026-11-10 20:00 北京时间 / 12:00 UTC，取官方文章结构化字段 datePublished；13:17:48 UTC 的 dateModified 不用于入窗判断。

**发生了什么**：DeepMind 发布 AlphaProof Code 研究结果，以人类确认的安全规格为约束，让多智能体证明 libsignal 参考实现所对应机器码满足指定安全性质，并公开验证材料。本文将事件限定为本次研究发布，不把更早创建的仓库当作今天首次创建。

**技术机制**：先把安全要求写成 Lean 规格，由人类审阅确认；未修改的 Rust 实现通过常规编译器生成 AArch64 Linux 可执行文件，置于形式化机器语义中推理。证明智能体负责提出证明，验收端用 Lean 内核检查，并用 comparator 对照保留的规格副本，防止智能体通过削弱定义“完成证明”。规格的修改另行审查，不能靠生成者自行宣告通过。

**关键指标/资源**：技术论文报告约 650 万行机器检查的 Lean 证明，以及约 2.6 万行需要信任的规格与 AArch64 语义（自述数据，未见第三方复现）。这不是模型通用编程能力得分，也不能用证明行数推算人工效率提升。论文还报告重新引入 2 个已修复历史漏洞后，可证明变异程序违反相应符号安全性质（自述数据，未见第三方复现）；不是发现 2 个仍可利用的新漏洞。

**为什么重要**：可被确定性检查器判定的证明，为多智能体长程工作提供了比“看起来正确”更强的验收条件。值得借鉴的是固定规格、隔离生成与验收、显式管理可信假设，而不是照搬智能体数量或证明规模。

**限制与口径冲突**：证明覆盖 PQXDH 握手与 Triple Ratchet 的指定性质，依赖密码学原语假设、受信任函数契约、Lean 内核与机器语义；符号模型和计算模型的量子安全边界不能混称。机器语义针对单线程、静态链接进程，不覆盖线程、动态链接等所有真实部署环境；这也不证明客户端 UI、服务器、设备安全或整个生态没有漏洞。官方文章元数据写“超过 300 万行”，正文写“超过 600 万行”，技术论文写“约 650 万行”，本期明确采用论文口径，差异原因仍待核实。本次未运行全部证明。

**开放与许可**：仓库与技术材料可公开访问。GitHub 许可证检测为 NOASSERTION；根 LICENSE 列有第三方代码的 MIT、AGPL-3.0 等分项条款，不能将整个仓库概括为单一 Apache/MIT 许可。具体文件复用权限须逐项核对。

## Agent 基础设施 · 本机工具与行业工作流

### 2. n8n Nod 研究预览：本机个人 Agent 公开发布并更新至 v0.6.1（n8n Labs）

**第一信源**：[官方发布](https://blog.n8n.io/meet-nod/)；[项目与文档](https://nod.n8n.io/docs/)；[官方仓库](https://github.com/n8n-io/nod)；[v0.6.1 发布记录](https://github.com/n8n-io/nod/releases/tag/nod-v0.6.1)。

**首发时间**：本次公开发布文章为 2026-11-10 20:52:49 北京时间 / 12:52:49 UTC；v0.6.1 的官方 published_at 为同日 20:08:16 / 12:08:16 UTC，均在窗内。仓库早于本日创建，v0.6.0 也已在前日发布；不宣称这是 Nod 的第一行代码或首个历史版本。

**发生了什么**：n8n Labs 正式介绍独立于 n8n 主产品的 Nod 研究预览。它是带独立浏览器与本地运行环境的个人 Agent，可使用选定模型访问应用、处理网站任务、保留可编辑记忆，并连接 n8n 工作流。同期 v0.6.1 包含后台成本显示、模型配额错误说明、长研究结果以 Markdown 文件交付等改动；后台成本下降未披露可比量化指标。

**技术机制**：任务在本地虚拟机及其浏览器中执行；应用、记忆和凭据保留在用户设备，云端模型调用仍会传输完成任务需要的信息。用户可接自有模型 API、受支持的订阅连接方式或本地开源模型。对发送消息、付款、发布、删除等动作另设权限检查，并保留操作与成本记录；网页、邮件中的文字本身不能代替用户授权。

**关键指标/资源**：官方报告 LongMemEval 得分 93.2%（自述数据，未见第三方复现），本期未复跑该评测，不能外推为真实任务成功率。官方给出的默认单任务消费确认阈值为 5 美元，这是产品控制项，不是任务平均成本或费用上限保证。

**为什么重要**：个人 Agent 的工程重点正从聊天入口转向可持续执行、可检查权限、可管理记忆和可追踪成本。Nod 提供可检查的实现与桌面入口，但“本机 Agent”不能被简写为完全离线或零数据外传。

### 3. Gemini for healthcare 美国预览：把权限继承与可追溯引用接入医疗 Agent 工作流（Google Cloud）

## 趋势简评

- **可靠性来自不同层次的约束**：AlphaProof Code 用形式化检查器约束证明；Nod 用权限模型约束操作；医疗 Agent 用身份权限、引用与人类审阅约束工作流。三者不能被统称为同等强度的“安全保证”。
- **开放状态需要拆开判断**：代码可访问、许可证明确、模型可本地运行、数据不用于训练是不同问题。Nod 的 Apache-2.0 不解决云端数据流问题，公开证明仓库也不免除可信规格审阅。
- **自主研究不等于递归自我改进**：证明智能体能自动完成长程任务，不代表系统证明了模型权重自我提升或开放式 RSI；本期不作此推论。
