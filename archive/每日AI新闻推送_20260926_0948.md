### 2. Anthropic 生命科学研究组首发成果：约 950 个 Claude 智能体并行 21 小时、消耗 2.1 亿 token，自主发现未表征噬菌体酶系统 ART（类 CRISPR 重复阵列）（Anthropic 官方 / arXiv 预印本 | 2026-09-23 美东）

**事件概述**：
9 月 23 日（美东周三），Anthropic 宣布其 2026 春季组建的生命科学研究组及湾区生物实验室的首发成果：在人类研究者仅给出高层检索方向的前提下，约 950 个 Claude 智能体并行运行 21 小时、消耗约 2.1 亿 token，从 20 万+ 逆转录酶（RT）中筛出 3,500 个候选系统并聚焦 20 个重点对象；其中一个智能体在查看某噬菌体异常 RT 旁的原始序列时发现一排间隔规则的重复 DNA，提交人工复核后确认为此前未完整表征的**阵列相关逆转录酶系统（ART）**——含逆转录酶、功能未知的伴随蛋白基因、以及类似 CRISPR 的规律重复 DNA 阵列。张锋（MIT/Broad，CRISPR 先驱）审阅预印本后评价「genuinely intriguing and merits further investigation」。

**技术与工程价值**：
- **核心机制**：这是**多智能体自主科学发现**（RSI 方向的科学应用实例）的标志性案例：① 开放式检索任务——人类不给具体目标分子，仅给「找有趣的 RT 系统」的高层提示，Agent 自主决定「什么值得关注」（决策层自动化）；② 大规模并行（950 Agent × 21h × 210M token）+ 漏斗式筛选（200k→3.5k→20），把专家需数周至数月的文献/数据库分析压缩至小时级；③ 人机分工明确——AI 负责数据检索/候选筛选/假设整理，湿实验由湾区 BSL-1/2 实验室人类科学家完成，ART 的生物学功能仍待实验确认。
- **实际影响**：与第 70 跑「OpenAI RSI 三件套」（治理制度化）不同，本条是 RSI/自主研究智能体在**生命科学**领域的首个公开落地样本（此前 Anthropic 有 Claude for Protein Design/Chemistry，本条扩展至基因组挖掘）；若此类开放式检索可复现至其他领域，「AI 生成假设 → 人类验证假设」的研究产能瓶颈将从「假设生成」转移到「实验容量」，实验室吞吐量成为新约束。预印本已发布但功能验证未完成，**ART 是否具备基因编辑能力尚不确定**。

**关键指标/资源**：
- 评测/性能：950 Agent / 21h / 210M token / 200k RT → 3.5k 候选 → 20 重点（发布方自述，待核实：第三方复现尚未出现）；ART 重复阵列可表达、产生一组不同短 RNA（Anthropic 湾区实验室初步实验，非同行评审）
- 代码/论文：Anthropic 官方博客 + 技术预印本（9/23 美东）；张锋审阅评价（第二信源）

### 4. 苹果开源 LensVLM-9B：基于 Qwen3.5-9B-Base 的视觉语言模型，「压缩扫描→选择性展开」范式，长文档 token 消耗降 84%（Apple / Hugging Face | 2026-09-23 至 9/24 上架，9/25–26 窗口内为 HN 首页 + 集中报道期）

**事件概述**：
9 月 23–24 日，苹果将 9B 参数视觉语言模型 **apple/LensVLM-9B** 上架 Hugging Face（基础模型标注「Built on Qwen3.5-9B」），同日论文（arXiv:2605.07019，5 月 7 日提交）登上 HN 首页并引发「苹果开源中国基座模型」的讨论。模型定位**长文档 VLM**：将整份 PDF 渲染为低分辨率压缩图像（每页视觉 token 数固定），先「远扫」判断相关页，再对锁定页做高清展开（文本或高分辨率图像两种展开格式），论文称 4.3× 有效压缩下精度接近全精度上界、10.1× 压缩下仍优于检索/文本压缩/视觉压缩基线；token 消耗降约 84%、KV cache 从 ~1.6GB 压至 ~250MB。权重许可为**研究专用（非商用）**。

**技术与工程价值**：
- **核心机制**：本条的核心价值不在「9B 模型本身」而在**「压缩扫描→选择性展开」的文档理解范式**：① 文档以图像渲染（非 token 化），分辨率成为可调压缩旋钮；② 训练 VLM 识别「自己读不清哪里」并调用 `read_page` 工具展开该区域——**学习型工具调用**解决「压缩必然失精度」的硬约束；③ 展开格式由文档类型决定（渲染文本→展开为文本、原生文档→展开为高清图像），模型学会在何种场景调用何种工具。这与第 71 跑「MiMo HySparse2」（prefill 算力砍 5×/KV 显存砍 4.5×）的推理加速路线互补——HySparse2 解决「通用长上下文推理成本」，LensVLM 解决「文档理解场景的 token 预算」。
- **实际影响**：对 RAG/文档 QA/合同分析/代码库理解等长文档工作负载，「渲染为图+选择性展开」提供了比「逐页切块+向量检索」更低的 token 开销且保留版面/表格/配图信息；但**研究专用许可**意味着企业需将范式移植到自有 VLM 或等苹果开放商用许可，「苹果开放权重但底层是中国基座」的信号价值（降低开源基座使用门槛、跨阵营生态互认）大于模型本身性能。

**关键指标/资源**：
- 评测/性能：4.3× 压缩精度≈全精度上界、10.1× 压缩仍优于基线、token 消耗 -84%、KV cache 1.6GB→250MB（论文自述，7 项文本 QA 基准，待核实：第三方独立复现尚未出现）；上架 4 天 455 下载/169 点赞（HF 数据，2026-09-25，第二信源）
- 代码/论文：`huggingface.co/apple/LensVLM-9B`（9/23–24 上架）；arXiv:2605.07019（5/7 提交）；GitHub 代码仓库 + demo（论文提及）
- 标签：`#开源模型` `#VLM` `#文档理解` `#推理加速` `#国产基座`
