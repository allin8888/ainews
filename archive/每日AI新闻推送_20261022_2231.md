### 1. VS Code 1.143 稳定版：Copilot Harness 成为新会话默认，多模型并行对比进入预览（Microsoft / GitHub Releases | 2026-10-22）

**事件概述**：
微软发布 VS Code 1.143.0 稳定版，编码 Agent 会话默认切换到构建在 Copilot SDK 之上的「Copilot harness」，同时把「同一任务多模型 / 多 harness 并行求解再对比合并」做成预览功能，并首次把本地设备模型（MAI Code 1.1 Flash）作为实验性推理后端引入 IDE。

**技术与工程价值**：
- **核心机制**：harness（执行框架）与 model（权重）在架构上解耦——默认 harness 由 Copilot SDK 承载，企业策略可强制走 Copilot 并禁用 Local / Claude / Codex harness；Compare Models 让同一任务在不同「模型 × harness」组合上并行跑，再横向比较与合并解法；on-device 实验路线把推理下沉到本地 GPU，官方明确其不消耗 AI credits 但仍需 GitHub 登录；配套工程能力包括 Agent 会话 worktree 的存储回收、可查看与停止的分离式后台 shell、以及语音模式自带密钥（BYOK，使用用户自己的 OpenAI API Key）。
- **实际影响**：编码 Agent 的「默认运行时」从外挂 CLI 收敛为 IDE 原生抽象，harness 选择第一次成为可在产品内 A/B 的一等工程变量；本地模型作为实验后端，为源码不出域（受监管代码库、私有内核）场景给出了显性的硬件门槛下界，也把「谁为 token 付费」的成本模型从订阅额度推向设备能力。

**关键指标/资源**：
- 评测/性能：本地实验模型 MAI Code 1.1 Flash 要求 NVIDIA GPU 显存 96 GB 以上（厂商文档口径，未见第三方实测）；1.143 文档页标注里程碑日期 2026-10-19，而 1.143.0 稳定版 GitHub Release 发布时刻为 2026-10-22 21:00（北京时间，窗口内），两处口径差异已列入「待核实」。

### 2. OpenClaw 2026.10.6：把「已修补的 Node 运行时」变成硬依赖，拒收受损密钥签名的 TLS 链（OpenClaw / GitHub Releases | 2026-10-22）

**事件概述**：
智能体运行时框架 OpenClaw 发布 2026.10.6，要求 Node 24 线 ≥ 24.22.1 或 26 线 ≥ 26.12.1——这些版本会拒绝由 2026 年 10 月 Node.js 安全公告中被泄露的证书私钥签名的 TLS 链；Docker 镜像内置 Node 24.22.1，`openclaw update` 在旧 Node 上先拒绝安装并给出恢复指引，源码构建固定 pnpm 12.15.0。

- **实际影响**：这是「Agent 基础设施」从能力竞赛转入可靠性与供应链治理的一个具体样本：长程任务最常见的失败模式（消息丢失/重复、静默挂死、有损迁移）被逐项工程化封堵，同时给出框架强制 TLS 供应链策略的可复制范式——与本窗口内第 1 条的 harness 权限治理、第 4 条的凭证滥用事件构成同一条主线。

**关键指标/资源**：

### 3. Sierra 发布 τ-Entity：语音智能体实体采集基准，最优系统 pass@1 60.3%、pass³ 34.0%（Sierra Research 官方博客 | 2026-10-22）

**事件概述**：
Sierra 于 22:02（北京时间）发布 τ-Entity 基准，专测语音 Agent 能否正确采集姓名、电话、地址、邮箱等细节，识别自己可能采集错了，并在错误扩散到后续动作前修复；规模为 200 个任务 × 10 类实体 × 6 种语言，沿用 τ-bench / τ²-bench / τ-i18n 的多语言覆盖设定，并区分常规通话、噪声密集与语音密集三类声学条件。

**技术与工程价值**：
- **核心机制**：把评测最小单元从「任务是否完成」下沉到「实体级三元回路：采集—怀疑—修复」，从而把 ASR 感知误差与对话策略误差分离度量；pass³（同一任务连跑三次须全对）替代单次通过率，直接压出「碰运气答对」的空间。
- **实际影响**：头部语音系统从单次 60.3% 掉到三次全过 34.0%，说明细节型可靠性而非平均能力才是语音 Agent 上线客服/工单流的瓶颈；「被核查的初始错误采集中最终仅 24–37% 被改正」直接量化了自我纠错回路的缺失，与 τ-bench 谱系此前在工具-用户闭环上的结论一致：Agent 的失败主要来自不会承认与修正错误，而非单次推理能力不足。

**关键指标/资源**：
- 评测/性能：GPT Live 1 pass@1 60.3% / pass³ 34.0%；Grok Voice Think Fast 2.0 44.2% / 24.0%；Gemini 3.8 Live 43.8% / 19.5%；初始错误采集经验证后最终改正比例 24–37%（全部为发布方自述评测，未见第三方复现；未提供级联 ASR+LLM+TTS 基线数值）。
- 代码/论文：[官方博客](https://sierra.ai/blog/tau-entity-can-voice-agents-get-the-details-right) ｜ [arXiv:2609.13602（τ-Voice 谱系论文）](https://arxiv.org/abs/2609.13602) ｜ [榜单 taubench.com](https://taubench.com)；基准数据/代码是否开源官方帖未说明（待核实）。
