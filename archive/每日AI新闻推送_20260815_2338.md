## 1. Scale AI 提出「Model or Harness?」：41 种 Agent 失败模式的交互中心分类法
- **事件**：Scale AI 七位研究者发表《Model or Harness? An Interaction-Centric Taxonomy for Localizing Agent Failures》，把 Agent 失败归因为「组件之间的交互边 + 故障侧」，系统性列出 **41 种失败模式**，覆盖 Model / User / Harness / Environment 三大家族、九类组件（Model、Owner、Grader、Third Party、Context、Memory、Tool、Local Env、External Env）。以四个前沿模型作独立评判者，最强评判者 GPT-5.5 与人工标注 Cohen's κ=0.76，四模型全票一致时精度 0.96。
- **为何值得关注**：直击 AI Coding 工程的核心痛点——同一可见失败可能需改模型、改脚手架（harness）或改环境，论文提出「修复归属问题（repair-assignment problem）」，把"Agent 挂了→换更大模型"的膝跳反射转为可路由的工单。与本期七周主线「增量在模型之外」形成方法论层面的呼应。
- **来源**：arXiv:2607.28802（7/30 提交）；8/15 经社区长帖（X：@rohanpaul_ai / DAIR.AI @omarsar0）二次引发讨论。

## 2. 《Same Task, Different Work》：提示词如何让编程 Agent 空耗 2.4–18× 算力而无收益
- **事件**：一项预注册研究（**4,644 次有效运行**、24 个确定性任务、7 个推理模型、PI.DEV 与 Claude Code 两套真实 harness）发现：要求"多种方案"使推理量膨胀 **2.4–7.4×** 且产生约 3 个被弃用的方案分支、成功率不变；"务必确定"类指令触发冗余验证，最高使单次运行成本达基线 **18.25×**、工具调用 2.5×、耗时 3×，成功率仍无提升；harness 设计本身可把"每成功任务成本"改变 **5×–30×**。结论通过冻结 holdout、改写测试、Kimi-K3 复现与 Claude Sonnet 5 研究验证。
- **为何值得关注**：把"Coding Agent 的提示词工程"从玄学变成可测量的「工作设计」——决定 agent 想什么、执行什么、何时停。对 AI Coding 成本治理（与 8/8 Databricks、8/12 Docker Sandboxes 同属"把控制点下沉到工程层"）是直接补充。
- **来源**：arXiv:2608.01347（8/2 提交，v3 8/6）；AI HOT 收录（X：@rohanpaul_ai）。

## 3. Codex 自动研究把内核 QR 分解压到 232× 加速
- **事件**：开发者在 GPU Mode × Core Automation 的 auto-research 竞赛中，以 Codex 为执行引擎、自身做领域 steering，用「分块 Householder + WY 表示（GEMM 更新）」重写批处理方阵紧凑 QR 分解，**14 天 1500+ 次提交**，将基线 torch.geqrf 约 419ms 压到 1.8ms（≈**232×**），排名 12/183。工作流含 AGENTS.md + 日志、`/goal` 定量自循环、Modal/NCU profiling、beam of candidates 防局部最优。
- **为何值得关注**：展示 Coding Agent 在系统级性能优化（Triton/CUDA kernel）中的真实生产力——不是写业务代码，而是"自主分析—提出优化—迭代验证"的科研式循环。呼应 8/11 Anthropic 黎曼 ζ、8/15 上午 ICML 复现的「研究 agent 基础设施」主线。
- **来源**：sankalp.bearblog.dev/autoresearch（博客内容已核验）；AI HOT 收录。

## 4. 工具调用转向「代码优先」：14 个模型中 11 个优于 JSON
- **事件**：新研究对比 JSON 与代码优先（code-first）工具调用，在 14 个模型、309 项 BFCL v4 任务上，程序化调用在 **11 个模型持平或胜出**；GPT-5.6-Sol 与 Terra 各提升 10.6 个百分点；Claude Sonnet 5 在 100 次调用时 JSON 枚举准确率降至 0%、Python 保持 100%；13 个模型的顺序链执行更快。
- **为何值得关注**：对 Coding Agent 的工具层设计有直接影响——用可执行代码（而非 JSON schema 枚举）表达工具调用，在大模型上更稳定、更快、更易组合。与本期「模型之外的工程层决定上限」主线一致。
- **来源**：AI HOT 收录（X：@rohanpaul_ai 转述论文）；论文原文（BFCL v4 基准）**待核实**。

## 5. OpenAI 对话前端优化：agentic 时代瓶颈从模型转向客户端
- **事件**：OpenAI 将 741 轮、231MB 对话的前端 transcript 加载从 **15,529 条砍至 64 条**，耗时 27s→1.66s，网络请求 894→16，JS 堆内存增长降 87.8%；Brent 称 forking 与 side chat 接近瞬时，覆盖 CLI、所有应用与模型。
