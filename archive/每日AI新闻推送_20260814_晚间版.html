一、Cursor 正式被 SpaceX 收购：编程工具接入全球最大 GPU 集群

事件：8/14（北京时间约 20:00），Cursor 官方博客确认已被 SpaceX 正式收购，完成自 4 月启动的收购流程（此前为与 SpaceXAI 的模型训练合作）。合并后 Cursor 将接入 SpaceX 全球最大规模 GPU 集群，用于训练更强且运行成本更低的模型，并以更低价格向客户提供更强大模型；官方称周三发布的 Grok 4.6 是双方合作成果的早期体现。

为何值得关注：这是 AI Coding 工具从「套壳/编排层」走向「自有算力 + 自有模型」的标志性整合——直接呼应本系列「去模型化 → 接入层 → 运行时标准化」主线的最新落点：当头部 Coding IDE 拥有底层算力，模型能力、定价与迭代节奏将更多由工具厂自身掌控，开发者入口竞争进一步上移到基础设施。

二、智谱 GLM-5.3 发布：开源编程能力登顶，并涌现网络安全能力

事件：8/14（北京时间约 13:31），智谱发布 GLM-5.3（基于 GLM-5.2 基座、极致后训练 Scaling）。官方称编程能力较前代提升 50%，在 Terminal Bench 3.0 等公开基准取得「开源第一」、接近 Claude Fable 5；白盒代码审查等安全任务表现持平 Mythos 5，CyberGym 得分 84.5%；权重将于两周后开源，即日起上线 ZCode、AutoClaw 等工具。

AI Coding · 模型

三、通义千问开源 Qwen3.8-27B：原生多模态稠密模型，262K 上下文可扩 1M

事件：8/14（北京时间约 23:02），通义千问开源 Qwen3.8 系列新成员 Qwen3.8-27B——原生多模态稠密模型，仅 27B 参数即整体超越 Qwen3.7-Plus，原生支持 262K 上下文（可通过 YaRN 扩展至 1M tokens），采用 Apache 2.0 许可，便于本地轻量部署。Max 级 Qwen3.8-2.4T-A95B 的开放权重亦同步在列（该 2.4T 版本已于 8/13 先行发布）。

为何值得关注：在 2.4T 旗舰开源之外补上「小参数原生多模态」档位，使 Qwen3.8 形成「旗舰 / 稠密全开放」的产品矩阵；对 AI Coding 而言，27B 多模态稠密模型适合端侧 / 私有化 agent 与多模态代码理解场景，Apache 2.0 进一步降低商用门槛。

来源：X：通义千问 / Qwen (@Alibaba_Qwen)；https://x.com/Alibaba_Qwen/status/2088280182356611304

Agent · 模型

四、小红书 dots3-note Preview 开源：280B 参数轻量模型，主打长程智能体与多模态推理

事件：8/14（北京时间约 19:25），小红书技术开源 dots3-note Preview——dots3 系列最轻量模型，总参数 280B、激活参数 16B，支持 512K 上下文及文本 / 视觉 / 语音多模态理解，针对复杂推理与长程 Agent 任务优化；配套 TEMPO 机制让同一智能体在每个宏观步骤切换为 critic，用测试时推理估计回报，为稀疏奖励长程任务的 RL 训练提供结构。

为何值得关注：以「MoE 小激活 + 长上下文 + 多模态 + 测试时 critic」组合切入长程 agent，是本周「性价比模型冲击前沿」主线的又一注脚；其 16B 激活参数在 512K 上下文下的推理成本结构，对长程编码 / 运维 agent 的部署经济性有参考意义。

具身智能 · 研究

五、具身 VLA 论文潮：内部任务进度可读 + 时序 GRPO 信用分配（8/13 提交）

事件：8/13（arXiv cs.RO）两篇 VLA 论文：

— Decoding Task Progress from VLA Representations（arXiv:2608.13474）：用机械可解释性方法探测 π0.5 残差流，发现「任务进度（轨迹剩余归一化时间）」可从激活中线性读出；该信号在 PaliGemma 骨干预训练阶段即存在，单个线性探针可泛化到未见任务，并用作无标签 OOD 检测器（检测任务停滞），性能与 SOTA 方法竞争。

— Temporal GRPO（arXiv:2608.13026）：针对 GRPO 式 VLA 后训练中「整条轨迹共享一个 rollout 优势」导致的「轨迹级信用混叠」，构造可检测任务阶段、仅在进入同一阶段的 rollout 间比较，将阶段优势作用于对应动作区间；在 RoboTwin 2.0 提升任务成功率与样本效率，LIBERO-Long 受控更新保留共享前提阶段。

为何值得关注：前者把「VLA 内部表示可解释、可运行时监控」从设想推向可用工具，承接 8/11 AtlasVLA 解决的「任务进度遗忘」问题，为部署态 VLA 提供轻量监控路径；后者把信用分配细化到阶段级，是 VLA 从「能跑」到「高效从稀疏反馈学习」的关键训练改进。两篇共同印证本系列「增量在模型之外（状态维持 / 训练结构）」主线在具身侧的延续。

来源：arXiv:2608.13474 / arXiv:2608.13026（8/13 提交）
