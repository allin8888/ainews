### 1. OpenCode 正式发布 Browse：MCP 服务器 + Chromium 扩展把「真实浏览器」交给编码智能体，登录/2FA/支付可人工接管（OpenCode 官方 X / 产品页 / GitHub anomalyco/browse | 2026-11-07）

**事件概述**：
OpenCode 官方 X `@opencode` 于 `2026-11-07T02:35:40Z`（BJ 10:35）宣布 Browse 正式可用，同日 GitHub `anomalyco/browse` 有 `store-listing` 上架提交（`11:43:21Z`，BJ 19:43）。产品由一个 MCP server 加一个 Chromium 扩展组成，让任意 MCP 客户端的 Agent 直接驱动用户日常使用的浏览器，复用已有的标签页、登录态与扩展，而不是另起一个干净的无头沙箱。

**技术与工程价值**：
- **核心机制**：① 接到用户真实 profile——Agent 用 Playwright 打开并驱动标签页，标签在后台以折叠分组呈现，不抢占用户当前窗口；②「Lend a tab」把用户当下已打开的标签直接交给 Agent，无需重新登录或注入密钥；③ 人机交接（Handoffs）：遇到登录、2FA 或支付这 **3 类高风险动作**时把标签交还用户，用户点 Continue 后 Agent 从中断点继续；④ 站点 Allowlists 把单次会话可访问的域名限制在用户点名的范围；⑤ 观测能力给出 **3 类观测产物**（截图、屏幕录制、网络流量 HAR）；⑥ 与 MCP 客户端解耦，OpenCode / Claude Code / Cursor / Codex / Zed 等任意 MCP client 可调用，覆盖 **8 类 Chromium 系浏览器**（Chrome / Edge / Brave / Arc / Helium / Vivaldi / Opera / Chromium）；安装走 Chrome 商店扩展 + `npm install -g @opencode/browse`（另有 curl / PowerShell / bun 脚本）。仓库 MIT 许可。
- **实际影响**：把「浏览器自动化」的前提从「给 Agent 一个隔离环境」翻转为「让 Agent 在用户已有的身份与会话里工作」，省掉密钥管理与重复登录这一层工程成本；同时把高风险动作显式留给人类、用 allowlist 缩小爆炸半径，是接入层而非模型层的增量。与同窗内 Vercel `agent-desktop` 所代表的「OS 无障碍树」路线对照：Browse 走浏览器内 Playwright / CDP，`agent-desktop` 走系统级 accessibility tree，二者是「把 GUI 接进 Agent」命题的两层不同切法。注意官方未给出成功率、延迟、并发标签数任何量化基准，也未说明扩展权限范围与后台标签的隔离边界；这是产品可用性与开源仓库层面的发布，不是能力跃升的评测报告。

**关键指标/资源**：
- 评测/性能：**无公开量化基准**（产品页只给能力清单，未见第三方复现）。可核验的结构性数字：支持 8 类 Chromium 系浏览器、3 类观测产物、3 类人工交接动作、任意 MCP 客户端；Chrome 扩展 ID `mfnicocicmmlkpjnaffgihfjhdgjkdjg`。

### 2. Strata 0.2.12 发布：12GB 显卡提示词读取提速约 3 倍，并把编码 Agent 的强制工具调用从 0/24 修到 24/24（GitHub Niko1221/Strata Release v0.2.12 | 2026-11-07）

**事件概述**：
GitHub Release `v0.2.12` 的 `published_at = 2026-11-07T08:54:40Z`（BJ 16:54）落在本窗内，是本期唯一有权威平台时间戳的一手首发。Strata 是 MIT 许可的本地推理引擎（C++，基于 llama.cpp / ggml 部分组件），让 MoE 模型 Qwen3.8-Flash-Next 在 12GB 消费级显卡 + 系统内存 + SSD 上跑起来；本版重点是调优 DFlash2 草稿模型、预算 GPU 的 prompt kernel，以及一整批面向 Claude Code / Codex CLI / OpenCode 的工具调用协议修复。

**技术与工程价值**：
- **核心机制**：① 专家分层——每 token 都需要的 attention / DeltaNet 混合器、路由器、共享专家、KV cache 与 MTP 草稿层常驻显存，其余专家 pinned 在系统内存由 CPU 与 GPU 并行计算，SSD 上放约 28.8GB 的 n-gram 查找表，两侧互不等待；② 12GB Linux 卡的第二次启动检查不再把引擎自身内存算作空闲，0.2.11 在 RTX 3060 上 3 次启动有 3 次误切到慢速文件缓存，0.2.12 为 0/3；③ 调优 DFlash2 草稿模型（0.34GB，Intel Arc 为 0.52GB，基于 Inco AI 的 Apache-2.0 权重）并扩大 Auto 启用范围，但在 AMD gfx1201（R9700 / RX 9070）上因 0.2.11 有 11/50 个引擎在 prompt 阶段卡死而默认回退到自研 MTP，界面明示原因，仍可 `--drafting dflash2` 强制；④ 工具调用协议层修复：`#4828` 多工具下强制 `tool_choice` 从 0/24 次成功到 24/24；`#4832` Anthropic tool result 正确跟随 `tool_use_id`；`#5312` Claude Desktop 的 `claude-5-5-sonnet` 映射到已加载模型；`#5409` / `#5276` / `#5281` 补齐 `<function=tools>`、`<toolcall>`、MCP 末段匹配等解析；新增 `undeclared_tool_calls`（默认 `text`，`call` 需显式开启）。
- **实际影响**：把「本地跑大 MoE」从可行性演示推向可被 coding harness 直接当作后端的工程件——引擎在 `127.0.0.1:8080` 同时提供 OpenAI `/v1`、Anthropic `/v1/messages` 与 Responses 风格接口，Claude Code 只需改 `ANTHROPIC_BASE_URL`。更值得记的是发布说明主动列出回归：RTX 3060 上 JSON 抽取 -18.9%、Strix Halo 工具调用 -9.5%（定位来自调优草稿模型）、双卡 peer 模式约 4% 冷启动首请求故障、gfx1201 强制 DFlash2 仍可能卡 prompt；并写明测量方法（同机 0.2.11 / 0.2.12 并排、2–3 轮、每轮交换顺序、每轮冷启动、greedy 300 token），同时保持 10 个工具调用 issue 开放。在普遍只报增益的自述基准里，把损失与口径一起发布是少见的工程纪律。

**关键指标/资源**：
- 评测/性能（**均为发布方自述，未见第三方复现**）：RTX 3060 12GB + UD-IQ4_XS-v31，prompt 2K 从 87 提到 264 tok/s、32K 从 361 提到 981 tok/s（约 3×），code +37% / agent +34%，但 JSON 抽取 -18.9%；Mac M5 Max 4K 1,406→1,605、32K 1,350→1,524 tok/s，输出 +12.7%；Strix Halo 4K 690→1,220、597→1,267 tok/s，但 tool call -9.5% / -5.8%；Radeon R9700 32K 3,076→3,304 tok/s（+8.6%~+11.6%）；调优 DFlash2 在 RTX PRO 5000 / DGX Spark 上 decode +2.4%~+5.0%；强制工具调用 0/24 → 24/24。发布 42 个文件共 9.70 GiB，附 `SHA256SUMS.txt`。
- 代码/论文：https://github.com/Niko1221/Strata/releases/tag/v0.2.12 （MIT；`curl -fsSL https://github.com/Niko1221/Strata/releases/latest/download/install.sh | sh`）

- **实际影响**：三点合起来把竞争点从单点模型演示移到「模型—世界模型—交付管线」的工程闭环：一步动作生成针对端到端延迟，神经符号双记忆针对家庭长时程一致性，6 管线与数据回流针对项目交付确定性。与本期 Browse、Strata 放在一起看，窗内三条分别落在「接入层（Agent 用谁的身份）」「执行层（模型跑在哪、工具调用协议对不对）」「交付层（现场数据能否回到下一版模型）」，共同指向同一件事——2026 下半年 Agent / 具身侧的增量主要不在权重，而在 harness 与工程闭环。
