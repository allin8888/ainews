1. 面壁智能 ForgeKernel：自进化算子生成系统同时登顶华为 CANNBench 三硬件榜与英伟达 SOL-ExecBench

第一来源：X @OpenBMB 官方账号 + 公开榜单 | 2026-10-28

事件概述：面壁智能（OpenBMB）官方账号公布自研 AI 算子生成系统 ForgeKernel 的打榜结果：同一套通用算子优化流程，同时在华为 CANNBench 的 950DT、950PR、A3 三张昇腾硬件榜单与英伟达 SOL-ExecBench（FlashInfer-Bench 合集）取得第一，把「Agent 自动写底层高性能代码」从实验室基准推进到两套互不兼容的硬件生态。

技术与工程价值

  • 核心机制：ForgeKernel 不设固定优化流程，模型按目标自主完成架构设计、编译、正确性校验与耗时剖析，并把每轮算子经验与硬件知识沉淀为可复用记忆，通过持续迭代实现自进化；其能力底座来自更早的极简通用 harness 实验 JustGoal（只给目标 + 通用工具），ForgeKernel 在其上补强长程规划与经验复用，而非沿专家预设路线逐步执行。
  • 实际影响：高性能算子长期受限于资深工程师逐芯片手写调优，新硬件上市到适配完成之间存在空窗。若 AI 能在新芯片发布初期直接产出可提交榜单的算子，国产算力从「能跑」到「跑好」的周期被显著压缩，等价于把已采购算力更早转化为可用吞吐；同一流程跨华为/英伟达复用，也降低多硬件路线的重复适配成本。生成结果已接入两侧训练框架并完成 MiniCPM5 0.9B 长训验证，说明产物进入了真实训练路径而不只停留在打榜。

  • 评测/性能：950DT 总分 3903.96（第二名 2846.61，领先 37.1%）、基准加速比 1.523×（第二名 0.305×）、提交 55/60；950PR 总分 3736.44（第二名 3552.34，领先 5.2%）、基准加速比 1.886×；A3 总分 4338.67（第二名 4049.50，领先 7.1%）、基准加速比 1.894×、提交 58/60；英伟达 SOL-ExecBench SOL 分数 0.814101 居首，同榜含 SF Tensor、Databricks、Qwen、Cursor 等团队。厂商供稿口径，待以榜单实时页复核

2. Mistral 推出 Responses API 公开预览：把推理过程与工具调用拆成独立条目，面向智能体逐步执行

第一来源：X @MistralAI 官方账号 | 2026-10-28

事件概述：Mistral 在官方账号宣布 Responses API 进入公开预览，定位为「在 Mistral 上构建智能体」的接口层：每次响应把模型回答、推理过程、工具调用拆分为彼此独立的条目返回，覆盖其托管的全部聊天模型（含 Large 4）。

技术与工程价值

  • 核心机制：以条目化响应取代 Chat Completions 的单段文本返回，使客户端可逐步消费推理轨迹与工具调用结果，匹配 agent 循环中「一次动作—一次观察」的结构；同一接口层适配多模型，降低自研 agent 框架的模型适配成本。
  • 实际影响：这是对 OpenAI Responses API 语义的事实跟随，意味着 agent 侧接口约定正在收敛：可观测的中间步骤、可寻址的工具调用、把 reasoning 与 answer 分离的计费与审计粒度。对合规敏感的自建 agent 团队，多了一条不绑定单一供应商的等价接口路径。

3. 小红书 2049 Lab × Rokid：蜜薯 Personal Agent 的智能眼镜架构——实时多模态全双工 + Proactive + Memory

第一来源：公众号「小红书技术 dots.llm」| 2026-10-28

事件概述：小红书 2049 Lab 发布与 Rokid 合作的 AI 生活助手「蜜薯」技术长文，披露其在智能眼镜上支撑「边看边聊」的三段式架构：实时多模态全双工链路、主动触发（Proactive）与记忆（Memory）协同，把大模型能力、社区经验与个人情境接入现场感知。

技术与工程价值

  • 核心机制：与桌面 agent 的一问一答不同，眼镜侧的核心约束是打断与并发——用户随时说话、环境随时变化，链路需同时维持上行视觉流、下行语音合成与中途插话处理（全双工）；Proactive 决定「什么时候由 Agent 先开口」，Memory 把个人情境与社区经验挂载到当前场景，二者共同把感知转成有条件、可撤回的行动建议。文中把该路线指向 Personal OS 作为下一阶段目标。
  • 实际影响：这是具身智能「真实场景多模态交互」的低成本落地样本——不依赖机械臂与本体，而把感知—决策—表达闭环压到消费级穿戴设备，验证全双工与主动性策略在真实用户环境的工程可行性，也为端侧/云侧分工提供可复用的系统分层。

关键指标/资源

  • 评测/性能：技术文以架构与工程取舍为主，未公布端到端时延、主动触发准确率或记忆召回等量化指标（见「待核实」）。

4. 蚂蚁 inclusionAI 开源 UBTree：用 Unigram 与 Bigram 模型做并行树草稿的投机解码

第一来源：GitHub inclusionAI/ubtree + 项目页 | 2026-10-28

事件概述：蚂蚁 inclusionAI 上线 UBTree 项目页并新建公开仓库，释出其投机解码起草方法：以 Unigram 与 Bigram 语言模型并行构造候选验证树，一次前向联合起草多个分支，再由目标模型按树结构验证。仓库同时给出面向 Ling3 Tiny / Flash 的 HumanEval 对比演示，并附 Hugging Face 权重与 SGLang 分支。

技术与工程价值

  • 核心机制：主流树草稿方法（DFlash、DSpark 等）依赖较强起草模型的多次前向或序列内自回归展开，UBTree 改用极轻的 n-gram 统计模型（unigram + bigram）并行生成整棵候选树，把草稿成本压到接近常数级，再靠树形分支提升单步命中率；与目标模型严格对齐的验证协议保证输出与自回归解码一致，属无损加速。
  • 实际影响：起草器越轻，加速比越易在低显存与高并发场景兑现，尤其适合自研小模型（Ling3 系列）与服务端批量推理。对已部署 SGLang 的团队，提供分支而非重写栈，接入成本较低；n-gram 路线也重新打开「投机解码是否必须再养一个草稿模型」这一问题。

关键指标/资源

  • 评测/性能：项目页报告 Qwen3-8B 上 6.94× 加速、Ling3-Flash 上 5.36× 加速，并称在全部测试项上优于 DARTree。自述数据，未见第三方复现
