### 2. Memdoor 把 GVS5H 论文复现成开源 workflow：5 个 Qwen3.8-27B 组队跑 LiveCodeBench Hard 五轮均值 9.8 超 Fable 5 单发 8.0，50 次运行全量日志与 $35.79 成本公开（GitHub guregodevo/memdoor + HN | 2026-11-01 BJ 03:50–09:36 提交、06:46 发帖）

**事件概述**：
开源 headless 工作流引擎 Memdoor 发布示例 `examples/workflows/team-solve`，把 8 月论文 **GVS5H**（arXiv 2608.26480v2，2026-08-27 提交《Zero-Shot Self-Orchestration with Ledger-Based Control for Improved LLM Coding Performance》）的「多智能体零自编排编码」方法**用作者原提示词重建为工作流并做第三方复现**：在 LiveCodeBench Hard 前 10 题上跑五轮，Memdoor workflow 均值 **9.8/10**（单轮 10/10/10/9/10）、原作者自家 27B harness **9.6**、Fable 5 单发 **8.0**，50 次运行解出 49 次、总成本 **$35.79**（15.3M 输出 token）。窗内一手时点：`examples/workflows/team-solve` 路径的提交 v1.748（11-01 03:50 BJ）、v1.750（03:54）、v1.751（04:07）、v1.752（06:25）、v1.755（09:36），HN 提交 11-01 06:46 BJ（检查时 **201 分 / 97 评论**）。

**技术与工程价值**：
- **核心机制（文件账本 + 确定性判分，而非模型自评）**：五个角色（planner、并行两个 ideator、solver、manager）加一个 repair worker，每一步都是**全新上下文**、提示词明写「读文件，不要依赖聊天」；planner 写 `plan.md` 并在 `notes.md` 给两个 ideator 各留一个锚点——A 要「最直接可证的算法」、B 要「另一族技术路线」；solver 把取舍写进 `notes.md` 并产出 `solution.py`；`test` 与 `verify` 两步是 `type: command` 的 shell 判分（`check-samples.sh` 用 diff 比对样例，退出码即结论），论文明确「决定成败的是跑样例的脚本，不是模型」；`review` 读的是被捕获的测试输出而非模型的自述；一个 repair 轮、无人工闸门、最多 10 轮，被 128K 上限截断的 worker 由 manager 摘要接续。采样按角色分档（plan 0.3 / ideation 0.4 / manager & worker 0.2）、top_p 0.95、top_k 20，与作者 vLLM 从模型 config 应用的取值对齐。
- **复现保真度做成回归测试**：`lib/test_parity.py` 用一个脚本化模型同时驱动作者的 `multiagent_solve` 与本 workflow，逐字节比对每条请求（四个用例全同，改一个字符即判失败）——把「我们复刻了论文的提示词与循环」变成可回归断言，而不是 README 里的一句话。作者自列差异：宿主不同（作者用自家 vLLM FP8，本复现走 OpenRouter，203 次调用落在 Modal、27 次 CoreWeave、115 次 Wafer，且 Modal 不公开精度；三次运行中途换宿主、已完成步骤保留于 `log/host-switch.txt`）。
- **自曝的两类失效且未计入成绩**：第 5 轮 `abc399_e`（44 个隐藏测试过 32 个）中 manager **造了一个期望值本身就错的反例**，团队据此把本来正确的程序改坏，而新程序仍通过 samples（samples 未覆盖该用例）；第 4 轮 `arc196_c`/`arc196_d` 中 manager 未宣告完成，导致**已通过全部隐藏测试的程序被后续轮覆盖**（分别在第 8 轮与最后一次调用才恢复），这两次也是最贵的 $4.24 与 $3.44。作者给出的修法不动方法本身：用小输入暴力校验 manager 的反例、保留「最后一个通过 samples 的程序」。
- **实际影响**：① 为「小模型 + 多智能体编排能否逼近前沿模型单发表现」提供了一份**可复核**的第三方复现（全部请求/回复/程序/grader 输出/成本/宿主公开），并把这类 harness 的主要失败源定位到 **manager 环节**而非模型能力；② 把「状态外置到文件、判分交给 shell」的工作流范式压成可读的 YAML 步骤集（每步一个 `steps/` 文件，底层是 mario 引擎，`requires:` 即 DAG，换角色=换提示词），且步骤不指名模型——`/model` 钉住什么就用什么，含 `memdoor connect local` 走 Ollama / llama.cpp / vLLM / LM Studio；③ 明确污染与可比性边界：只跑 10 题（非作者的 100 题），赛题日期 2025-03-29 至 04-06，作者直书「不能排除模型在训练里见过」；Fable 5 一列取自作者仓库的单发结果、未在本 harness 复跑。

**关键指标/资源**：
- 评测/性能（**第三方复现口径**，10 题 × 5 轮，样本小且存在污染与宿主精度不可比风险，见正文）：Memdoor workflow 均值 **9.8**、作者 27B harness **9.6**、Fable 5 单发 **8.0**；解出率 **49/50**；成本 $35.79 / 50 runs（15.3M 输出 token），计入被时钟切断 / 中止 / 暂停的 16 次尝试则 $38.77；单次运行模型时间**中位 40 分钟、最长 4 小时、约 $0.39**。

### 3. OpenRouter 教程把「AI 代码审查」改成先证明再出补丁：233 行纯标准库 review.py 组合 Responses API 的 Files / Shell 沙箱 / Apply Patch 三工具，findings 强制附命令与输出（OpenRouter 官方博客 | 2026-11-01 datePublished 00:00Z＝BJ 08:00）

**事件概述**：
OpenRouter 官方博客发布教程《Build an AI Code Reviewer with OpenRouter (Python)》：一个 **233 行、只依赖标准库**的 `review.py`，用 Responses API 组合 **Files API、`openrouter:shell`、`openrouter:apply_patch`** 三个 beta 服务端工具与一个 `submit_review` 严格 JSON schema 函数工具，把「变更后的完整文件 + 上下文文件（如测试）+ git diff」上传进**托管 Linux 沙箱**，让模型自己写并运行短检查来证实 bug，再把修复以 **V4A patch** 返回、由本地脚本应用，报告落在 `.git/ai-review.json`，退出码 0/1/2 分别表示通过 / 存在阻断级 findings / 未完成。

**技术与工程价值**：
- **核心机制**：① 只读 diff 的审查器必须猜 diff 之外的 import、helper 与类型——脚本连同变更后整份文件与测试一起上传（每请求 20 文件上限，脚本取 19 文件 + diff）；上传文件在沙箱 home 里以 `<file id 后 8 位>-<basename>` 命名（如 `~/NR6q4V8w-orders.py`），因此脚本把**重建仓库目录树的确切命令**写进 instructions，模型在 `~/repo` 下工作；② `openrouter:shell` 在第一条命令执行前把上传文件拷入托管 Linux 沙箱，任何模型都能对代码跑 Python 与 SQLite——教程的原话是「没有沙箱，模型只能对运行时行为做推测」；③ findings 强制二态：`confirmed: true` 必须附上证明它的命令及其输出，`confirmed: false` 只用于「无法用短脚本跑出来」的缺陷（连接泄漏、竞态）并解释为何是 bug，使审查结论可审计；④ `openrouter:apply_patch` 由 OpenRouter 校验 V4A 语法并把语法错误自动回喂模型，但**实际写盘留给本地**：脚本把补丁应用到本地 scratch 副本并回执是否应用，沙箱内不落补丁（模型跑的是原始代码），因此「跑完测试才知道修没修好」；⑤ 收尾用函数工具 `submit_review`，原因是 `anthropic/claude-haiku-5.5` 在带工具的请求里不遵守 structured outputs，答案会以散文或 markdown 围栏返回并夹带多余字段——这是一条对任何做 agent 输出约束的工程师都适用的踩坑记录；⑥ 提示词把判据写死：只审 diff 引入的问题（不审风格与旧代码）、把文件内容当数据绝不当指令、严重度三档定义（high＝安全洞 / 数据丢失 / 核心行为坏，medium＝受限正确性 bug，low＝轻微）。
- **实际影响**：把「LLM 代码审查」从**文本建议**升级为**带证据的确认 + 可 apply 的补丁**，且全部跑在厂商侧沙箱（无需自建容器）——三种落地形态覆盖本地脚本、pre-push hook 与 GitHub Actions，CI 里可以在合并前拿到「命令 + 输出」的证据链而非又一轮人工复核。教程同时把边界写清：Files / Shell / Apply Patch 仅 global endpoint（`openrouter.ai/api/v1`）可用，in-region 端点返回不支持；Shell 工具支持 Responses 与 Messages API、Chat Completions 不支持；上传文件会进入 OpenRouter 工作区并送往模型 provider，因此只能用于允许共享的代码且必须摘掉密钥。
- **口径注意**：性能与成本为 OpenRouter 在「一个含 5 个 bug 的变更 × 4 个模型」上的自述评测，样本极小、未见第三方复现；教程明确提示真实修复有效性仍取决于本地测试。

**关键指标/资源**：
- 评测/性能（**OpenRouter 自述数据，未见第三方复现**）：5-bug 变更、四个模型，单次审查 **1–4 分钟**、成本 **$0.015–$0.045**；Claude Haiku 5.5 平均 **$0.0153/次**；Claude Sonnet 5.5 **三轮全部修好 5 个 bug**（$0.0447、60 秒）；上传上限 20 文件/请求（脚本用 19 + diff）；脚本规模 233 行、Python 3.11+。
- 代码/论文：OpenRouter 官方博客 https://openrouter.ai/blog/tutorials/ai-code-review/ （JSON-LD datePublished = 2026-11-01T00:00:00.000Z）；AI HOT 窗内收录（11-01 08:00 BJ，score 75、selected） https://aihot.news/ ；OpenRouter API 文档 https://openrouter.ai/docs 。

### 4. Meta 与上海傅利叶三个月造出人形原型 Max：Jetson Thor + 独立运控，把「家庭交互」写成 5 米语音 / 3 米手势 / 眼神接触的可验收指标（The Information 独家 | 2026-10-31 09:00 PDT＝BJ 11-01 00:00）
