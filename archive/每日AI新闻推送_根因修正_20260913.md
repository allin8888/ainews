# 每日 AI 新闻推送 —「自动退出」根因修正（2026-09-13）

## 结论先行

任务"手动运行也自动退出"的**真正原因不是触发时间，而是 `qq-mail` 连接器未连接**。

WorkBuddy 自动化框架在真正执行任务前，会先校验任务所依赖的连接器。本任务依赖 `qq-mail`，而该连接器当前**未加载 / 未授权**，于是框架直接把运行**推迟（defer）并标记为失败**，运行记录随即被删除，调度器又把它保留为"待执行"再次派发——表现为"自动退出 + 反复重试"。

> 注意：本机连接器状态栏显示 **agent-mail（智能体邮箱）已连接**，但任务要的是 **qq-mail**，这是两个不同的连接器。qq-mail 才是缺失的那个。

---

## 铁证（来自磁盘真实日志）

### 1. daemon.log —— 每次运行都被 defer
```
[AutomationRunRuntime] connector subsystem not ready, defer run
  for automation-1784106545536/... (requested=qq-mail)
execute result automationId=automation-1784106545536 ...
  accepted=true, success=false, deferred=true, interrupted=false,
  error=connector subsystem has no loaded entries yet; deferring run (requested=qq-mail)
→ emit automations.records.changed ... status=DELETED
```
（同一模式在 9/12 10:25 起反复出现，每次间隔约 30s，直到被调度器不断重试。）

### 2. automation.log —— 被记为失败 + 警告
```
[WARN] run failed for automation-1784106545536:
  [UNKNOWN] 自动化依赖的数据源（连接器）均未连接成功：qq-mail。
  该任务为无人值守运行，已终止以避免产出无效结果；请检查连接器授权状态后重试。
```
该失败从 **2026-09-02 13:35 一直持续到 2026-09-10**，每天多次，全部 `success=false`。

### 3. 影响范围 —— 系统级，不止本任务
同机其他自动化也因同一 `qq-mail` 缺失而失败：
- `automation-1784106680013`
- `automation-1784107011006`

说明这是**连接器授权问题**，与任务 prompt 内容无关（prompt 本身未提及 qq-mail，是框架级投递依赖）。

### 4. 9/13 12:14 的"dispatch 风暴"解释
`automation.log` 在 12:14:04–12:16:55 每 ~5s 打出一条 `dispatch` + `run start`（`nextRunAt` 始终为 08:30 那次），却**没有任何 `run finished` / `error`**：
- 因为每次 run 都被 defer → 记录 `DELETED`，调度器认为"还没真正跑完" → 5s 后再次派发。
- 这正是"启动即退出 + 反复重试"的日志映射。

## 为什么早先的"08:30 太早"诊断不完整

9/13 早先一轮把问题归因为"08:30 触发时 app 未活跃 → 被静默跳过"，并把 rrule 改成 `FREQ=DAILY;BYHOUR=11;BYMINUTE=30`。
- 08:30 错过确实是**次要因素**（部分 scheduled 触发确实没点火）；
- 但即使改到 11:30、即使手动运行，任务依然跑不出来——因为**连接器这关过不去**，框架在真正执行前就 defer 了。
- 所以"改 11:30"只解决了触发时机，没解决"自动退出"。根因仍是 qq-mail。

## 修复方案（二选一，需你操作）

| 方案 | 操作 | 适用场景 |
|---|---|---|
| **A. 连接 qq-mail（推荐，若需要邮件投递）** | WorkBuddy → 设置 → 连接器 → 找到 **qq-mail** → 重新登录/授权 | 你确实想让日报通过 qq-mail 投递 |
| **B. 移除 qq-mail 依赖** | 若日报只需落到工作区 + 网盘归档（prompt 本身只要求写文件 + `present_files`），可把该自动化的 qq-mail 投递依赖去掉 | 不需要邮件，只想本地/网盘产出 |

> 提示：本任务 prompt 明确要求"生成 `.md` + `.html` 并归档到 `O:/quark/...`"，全程**不涉及发邮件**。qq-mail 依赖很可能是创建任务时默认挂上的投递动作，属于"多余依赖"。若你确认不需要邮件，方案 B 更干净、可彻底消除该阻塞。
