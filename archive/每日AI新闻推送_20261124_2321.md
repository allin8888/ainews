### 1. Anthropic 推出 Claude Ship：Code Review 正式 GA，PR Steward + Claude Approvals 把审批权交给 AI Agent（官方博客 | 2026-11-23）

**事件概述**：
Anthropic 于 11 月 23 日在 claude.com 官方博客发布 Claude Ship——一套把 AI 从「写代码」延伸到「提交后协作与交付」的 Agent 套件。它由已 GA 的 Code Review 与两个 beta Agent（PR Steward、Claude Approvals）组成，可在开发者发起 PR 后自动完成审查、修复失败检查与冲突、并按仓库内的审批策略文件决定是否批准常规变更。`/ship` 命令自发布当日起在 Claude Code 与桌面端逐步推送。

**技术与工程价值**：
- **核心机制**：Code Review 对 PR 做多维深审、对抗式验证发现项并分类，支持每仓库选择 Quick / Standard / Deep 三档审查级别；PR Steward 负责让 PR 保持「green」——处理失败 CI、合并冲突、来自审查工具与成员的反馈，每次 push 后留评说明改了什么、如何回滚，但明确**无权 approve 或 merge**；Claude Approvals 读取仓库默认分支上的 approval policy 文件（类「增强版 CODEOWNERS」，自然语言撰写），综合 Code Review 发现、团队自研分类器与自定义规则做出批准决策，可在策略允许时自动批准常规变更、否则升级人工复核。官方建议先以 observe-only 模式运行建立信任，再配合 branch protection 要求 approval 绿灯。
- **实际影响**：直指「AI 编码产能过剩、审批成为新瓶颈」——Anthropic 称其内部 Claude Code 团队大部分代码已由 Claude 编写，6 月至 9 月合并 PR 数量翻倍、被回滚比例下降超 40%。这是把「人类在环」从逐行审批上移到策略制定与例外裁决，Coding Agent 竞争从生成能力下沉到交付治理层。审批权委托同时带来新的治理面：官方明确 Ship 可能漏掉 bug/安全漏洞，且 ZDR、HIPAA、自管密钥组织不可用。

**关键指标/资源**：
- 评测/性能：官方自述内部数据——merged PR 6→9 月增加 **超过 2 倍**、revert 占比下降 **超过 40%**（无绝对数量，未见第三方复现）；Code Review 三档审查级别、每仓库可配 spend limit；Claude Approvals 无 base charge，策略中的分类器按 token 计费。
- 代码/论文：官方博客 https://claude.com/blog/introducing-claude-ship ；首发锚点：官方账号 X（ClaudeDevs）11-23 22:25Z / TechCrunch 11-23 22:05Z（均在窗口内）；凤凰网/网易 11-24 转载。
- 适用边界：仅 GitHub 仓库、Claude Team / Enterprise 计划；Code Review GA，PR Steward 与 Claude Approvals 为 beta；按 token 计费；不可用组织配置：Zero Data Retention / HIPAA / customer-managed encryption keys。

### 2. OpenAI × Cisco 开源 Shirudo：eBPF 运行时「自防御」盾牌，Codex 生成防护无重启拦截 Java4Shell（官方博客 / Cisco 投资者公告 | 2026-11-23）

**事件概述**：
OpenAI 与 Cisco 于 11 月 23 日联合发布开源安全运行时 Shirudo（日语「盾」），基于 Linux eBPF 在补丁推出前为运行中系统加载临时、可验证的防护层（shield），无需重启。项目以 BSD 2-Clause 开源（BPF 程序 BSD + GPL 双许可），GitHub 仓库 github.com/shirudo-dev/shirudo。这是「基础设施自防御、以机器速度对抗 AI 驱动攻击」的 Agent 驱动安全尝试，与 11-04 已报道的「948 个内核提权漏洞流水线」为不同事件（后者是漏洞发现能力，本期是运行时防护工程）。

**技术与工程价值**：
- **核心机制**：四大设计支柱——① **Live protection**：eBPF shield 在不重启系统的前提下阻断脆弱代码路径，部署前可先观察对应用的影响；② **Defense at machine speed**：Agent 获得可编程控制，调查漏洞、生成针对性 shield、对真实攻击与生产负载验证有效性，安全团队掌握最终部署权；③ **Trusted deployment**：shield 加载前经加密签名与校验，Linux eBPF verifier 检查安全规则、内核安全控制限制未授权变更；④ **Hardware-backed verification**：借助 TPM 记录防护加载/移除的可验证日志，即使主机管理员权限失陷仍可审计。受控测试中，Codex 生成一个向 Java Base64 解码器加输入检查的 eBPF shield，直接挂到运行中的 Elasticsearch 进程，拦截 Java4Shell 利用尝试且服务未中断。
- **实际影响**：把漏洞利用与永久补丁之间的「防御窗口」从人工节奏压缩到 Agent 节奏。Cisco CTO Thomas Graf 指出其是 Tetragon 运行时安全项目的演进——把内核遥测与执行机制适配给自主 Agent。签名 shield 可在一次团队验证后被全网复用，形成「防护即代码、随漏洞披露分发」的开源协作模式；代码已在 Linux Plumbers Conference 做技术演示，12 月 15 日安排深度研讨会。

**关键指标/资源**：
- 评测/性能：受控测试 1 项——Codex 生成 shield 成功阻断针对运行中 Elasticsearch 的 Java4Shell 利用（**厂商自述的受控演示，非生产环境独立评估，未见第三方复现**）；对 Java4shell 与 PHP 漏洞均写出检测并拦截代码（Cisco 公告口径）。
- 代码/论文：OpenAI 官方博客 https://openai.com/index/introducing-shirudo/ ；Cisco 投资者公告 https://investor.cisco.com/news/news-details/2026/Cisco-and-OpenAI-Launch-Shirudo-A-New-Project-to-Safeguard-Agentic-AI/default.aspx ；仓库 https://github.com/shirudo-dev/shirudo ；首发锚点 OpenAI 官网动态 11-23 21:20Z / Greg Brockman X 11-23 21:57Z（窗口内），中文媒体 11-24 转载。
- 适用边界：Python 侧无部署量数据、无生产环境统计；shield 定位为补丁前的临时防护，非替代永久补丁；OpenAI 明确长期目标尚需强化内核与核心服务。

### 4. Google DeepMind 开源量子程序形式化验证框架：Gemini 4 Agent 团队用 Lean 证明，arcsin 提速 290×、聚变模拟降本 11.8×（官方博客 / GitHub | 2026-11-23）

**事件概述**：
Google DeepMind 与 Google Quantum AI 于 11 月 23 日发布研究成果并开源 Lean 4 框架 `google-deepmind/formal-quantum-computation`：多组 Gemini 4 Agent 针对量子算法提出改进，每一项都用形式化定理证明器 Lean 验证正确性与资源成本后才进入共享知识库。因大规模量子电路无法在经典计算机或现有小规模量子处理器上实测，「机器可检查的证明」取代了单元测试成为验证闸门；这项 RSI 式「Agent 自主搜索 + 形式化验证」范式把 arcsin 状态制备提速 290×、聚变相关电路降本 11.8×。配套论文 arXiv:2611.09822（**11-06 首发预印本、11-16 v3，早于本窗口，本期以 11-23 官方博客 + GitHub 开源为首发锚点**）。

**技术与工程价值**：
- **核心机制**：在 Lean 4（扩展 Mathlib / Physlib）中构建量子程序库与量子 Hoare 逻辑，把量子门、寄存器、测量和经典控制纳入可证明体系；研究者为每个问题写「冻结规格」（含目标、误差界、T 门/qubit 成本上限，候选电路与证明留 `sorry` 占位）。多个独立 Gemini 4 Carbon 团队并行用数学推导、模拟、数值优化探索方案，候选须经 Lean 校验后才进入 shared notebook；每 4 小时各团队在「虚拟会议」交换、辩论、比较想法。设置外部验证器用 Lean Comparator 在干净沙箱复核每次提交，防止 Agent 通过削弱规格、放宽定理、注入占位公理（如曾发现对 Toffoli 门计数的投机，已通过重写规格堵住）造假。
- **实际影响**：这是「可验证的 AI 自主科研」的范式样本——Agent 提出、形式化检查器裁决、团队只在已证明结果上迭代，直击 LLM 科研「自信但错误」的软肋。论文量化：跨团队协作贡献约 39% 的性能提升（各科学问题 13%–63% 不等），说明 Agent 组织结构本身与模型能力同等重要。Apache 2.0 开源验证库、问题规格与已证明解，使外部团队可审计 AI 设计的量子电路与资源估计；但 Agent 编排系统仍为专有。

**关键指标/资源**：
- 评测/性能（**均为形式化验证的资源估计、非真实硬件实测，论文预印本未经同行评审**）：arcsin 状态制备 245 qubit×≥440,576 T 门 → 100 qubit×3,698 T 门，约 **290×**；惯性约束聚变电子停止功率成本降 **11.8×**、纠错 qubit 5,650→4,338；光敏分子模拟降本 **8×**；细胞色素 P450 降本 **2.5×**、内存 481→333 qubit；Grover 特定实现提速 **2.57×**。跨团队协作贡献性能提升约 **39%**。
- 代码/论文：官方博客 https://deepmind.google/blog/finding-faster-quantum-algorithms-with-agents-and-formal-verification/ ；仓库 https://github.com/google-deepmind/formal-quantum-computation （Apache 2.0）;论文 https://arxiv.org/abs/2611.09822 ；首发锚点 DeepMind 官方博客与 GitHub 11-23（窗口内），中文媒体 11-24 转载。
- 适用边界：结果均为资源估计（peak logical qubits × T 门数、平面 surface-code 架构），当前成本模型未计入经典计算开销；DeepMind 明确即使优化后仍需超出第一代纠错量子计算机的资源；证明只保证电路符合规格，不保证规格完整刻画物理。
