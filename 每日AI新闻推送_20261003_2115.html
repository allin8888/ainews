1. Hugging Face × Liquid AI 发布多 Harness RL 完整指南：同一权重在 Mini-SWE-Agent 得 62%、在 Claude Code 仅 33%，跨 4 Harness 训练后 held-out 42.2% → 54.2%

第一来源：Hugging Face / Liquid AI ｜ 2026-10-03
事件概述

Hugging Face 后训练团队与 Liquid AI 联合发布《The ultimate guide to multi-harness RL》，核心实证是一组令人不安的数字：完全相同的模型权重，在 Mini-SWE-Agent 中解决 62% 的任务，在 Claude Code 中只解决 33%。指南给出一套不修改任何 harness 代码即可在多个 Agent 框架内做 RL 训练的完整配方——用 capture proxy 记录 vLLM 实际采样的 token id 与 logprobs，配合 OpenEnv（环境）、Harbor（任务/沙箱）、TRL（async GRPO 训练器）三件套，在 Claude Code、Codex、OpenCode、Mini-SWE-Agent 四个 harness 上同时训练 LFM2.5-2.6B。

技术与工程价值
  • 核心机制：harness 控制 agent loop、工具集与上下文，因此训练者根本看不到模型真正吐出的 token——这是「同一权重、同一模型、不同分数」的结构性原因。解法是不改 harness，只改指向：在模型与 harness 之间插一层支持全部四种编码 Agent API 格式（OpenAI Chat Completions / OpenAI Responses / Anthropic Messages / Gemini）的代理层，harness 代码零改动即可获得训练信号。训练侧用 dense replay 在每个时间偏移构造预测窗口，存入增长中的 buffer 并采 mini-batch 更新。
  • 实际影响：这是「增量在模型之外」主线的又一次硬证据——决定 Agent 表现的主要变量正在从模型转向运行时。工程含义直接：跨 harness 泛化能力（而非单 harness 峰值）应成为开放模型发布的必测指标；同时 proxy 层本身成为新的基础设施位——谁掌握它，谁就能把任意开放权重模型训成任意 harness 可用的形态，模型分发权与 harness 适配权在这里合流。
关键指标 / 资源
  • 评测/性能：同权重 Mini-SWE-Agent 62% vs Claude Code 33%（训练前，held-out SmolDataEnvs 数据分析任务）；跨 4 harness 训练后平均 pass@1 42.2% → 54.2%；工具调用数 −31%（在基线与训练模型均解出的任务上）；仅在 OpenCode 训练的对照组达 52.3% 但仅在 OpenCode 内最优，两者 1.9 个百分点总体差距落在评估噪声内；对成功 rollout 做 SFT 的增益明显更小
  • 边界与代码：全部开源（OpenEnv + Harbor + TRL，HF Spaces FineEnvs/multi-harness-rl）；结论仅在 2.6B 小模型 + 数据分析任务上成立，未验证大模型或大规模软件工程基准（发布方自述口径，待核实）
  • 来源：rss.bz / Hugging Face multi-harness RL；AGI Hunt 10/3 汇总

2. DeepSeek Harness 全球公测并同步开源：基于 Cordis「一切皆插件」架构，桌面版打包 macOS/Windows，官方演示 5 分 24 秒自建并验证插件

第一来源：DeepSeek 官方公告 / Hacker News ｜ 2026-10-02 登 HN 首页，10-03 窗口内集中报道
事件概述

DeepSeek 将其开源编码 Agent 框架 DeepSeek Harness（dsh） 推向全球公测并同步开源，配套发布 macOS（Apple Silicon）与 Windows 64 位桌面构建，Linux 通过 deepseek-ai/dsh npm 包提供。Harness 建立在 Cordis 插件框架之上，官方定位是「一切皆插件」——模型适配器、工具注册、沙箱、会话日志、调度器乃至 agent loop 本身全部是可替换插件。官方演示中模型用 5 分 24 秒完成「创建 → 安装 → 验证」一个插件的全过程。

技术与工程价值
  • 核心机制：与 Claude Code 的约 30 个生命周期 hook 扩展点相比，Harness 允许直接换掉核心（agent loop 自身就是插件），架构文档给出的层序为：profile 中各 bundle（按列出顺序）→ profile 级 cordis.patch.yml → home 级 patch → 命令行 --patch 覆盖层，可用 dsh --profile web --dump-config 打印实际装载的插件树。DSH 把 Agent 的构成形式化为 Agent = 模型 + harness，与第 79 跑报道的 AWS Strands Decider 2B 属同一判断：决策/路由不应每次调用完整 LLM。
  • 实际影响：对成本敏感批处理与需要逐层审计的团队，Harness 的可自定义深度是当前开源编码 Agent 中最高的——第三方基准跑 DeepSeek V4 Flash 时，Harness 约 $0.028/成功任务 vs Claude Code 约 $0.195（约 7 倍成本差），token 效率 88,562 vs 649,900/任务，完成任务数 20/30 vs 19/30；代价是成熟度（第三方插件约 80 个，多为官方自产；安全审计未完成，官方文档明确警告「恶意输入或不可信插件可损坏文件或泄露数据」）。
关键指标 / 资源
  • 产品参数：MIT 许可；五种 profile（web / headless / sdk / sdk-minimal / acp）；支持任意 OpenAI 兼容端点与本地推理引擎（Ollama / LM Studio）；桌面版 v0.2，内置定时任务插件与执行 trace 调试器
  • 时间戳界定（重要）：Harness CLI 本身于 2026 年 8 月开源（首周 177,000 star），本次增量是全球公测 + 桌面版打包 + 官方插件生态启动；多源称公告于 10/2 登 HN 首页，确切发布小时数未在第一信源标明（待核实）
  • 成本对照为第三方基准（非 DeepSeek 官方数据，未见独立复现，待核实）
  • 来源：deniz.in 报道；codeyourcraft 架构解析

3. JEPA-TTT：世界模型在测试时持续自监督训练，500 episode 后潜在预测误差 −83%、规划性能较冻结 JEPA 提升 153%

第一来源：Honda Research Institute / JHU，NeurIPS 2026 World Models Workshop ｜ arXiv:2610.00722，2026-10-03 上线
事件概述

《JEPA-TTT: Persistent Test-Time Training of Latent World Models for Planning under Dynamics Shifts》提出一个直接对准具身智能核心痛点的机制：预训练的世界模型一旦遇到与训练分布不同的动力学（dynamics shift），预测即失效。JEPA-TTT 在测试期持续对动作条件化 JEPA 世界模型的潜在动力学预测器做自监督更新，且更新跨 episode 累积；视觉编码器与奖励头保持冻结，以保住预训练表征与任务目标。规划时既不需要目标图像，也不需要在线环境奖励。

技术与工程价值
  • 核心机制：dense replay——在每一个时间偏移处构造预测窗口，存入不断增长的 buffer 并从中采 mini-batch 更新预测器。相比「每个新环境重新微调权重」，这是把适应成本从训练成本转移到推理期数据积累成本。
  • 实际影响：把「部署后域自适应」从一次性工程动作变成随时间自动积累的在线过程——对动态环境（可变光照、载荷变化、磨损、他人干预）下的长时程机器人部署，直接消除了「新环境一来就要重训」的运维负担。这是本窗口内世界模型方向最具工程含义的一篇：它不追求更大更强的世界模型，而追求世界模型自己会变。
  • 与主线的关系：本跑第 4 条（Percepta Spotlight）把「能力增长不靠重训」做到推理架构层，本条把它做到世界模型的动力学层——测试时自适应正在成为继「更大模型」之外的第二条通用路线。
关键指标 / 资源
  • 评测/性能：4 个连续控制环境 × 8 种动力学偏移，全部偏移上规划均改善；500 测试期 episode 后自回归潜在预测误差平均 −83%，规划性能较冻结 JEPA 世界模型 +153%（论文自述数据，未见第三方独立复现，待核实）
  • 代码/论文：arXiv:2610.00722v1（cs.LG，NeurIPS 2026 World Models in Physical AI Workshop 录用）；项目页见论文内链
  • 来源：arxiv.org/abs/2610.00722

4. Percepta 发布 Spotlight 架构：用可写无界外部内存替换注意力，称访问成本不随内存规模增长

第一来源：Percepta（Christos Tzamos 团队）｜ 2026-10-03
事件概述

Percepta 发布新架构 Spotlight，核心主张是把「智能」与「记忆」解耦：计算模块的权重保持固定，知识、技能与工作状态存放在一个可写、无界增长的外部内存中，模型自行决定每个 token 加载与覆写什么内容。官方称这是首个「访问成本不随内存规模增长」的架构——每个 token 可读写无界内存，而生成只需常量级计算；其自述为「结合了注意力机制的记忆容量与固定状态循环模型的线性计算成本」，并声称相对注意力在长上下文上更优。

技术与工程价值
  • 核心机制：与 MoE 的固定稀疏不同，Spotlight 的稀疏度是任意可调的——模型逐 token 自行索引记忆单元。由于记忆可存储技能（不只是事实），模型能在不重训的前提下获得新能力。
  • 实际影响：若成立，则「上下文管理 / 技能积累」从外挂的 harness 逻辑下沉为模型内生能力，与本跑第 1 条（harness 决定 Agent 表现 62% vs 33%）形成有趣对照——两条路线都在削 harness 的权，一条是让模型自己学，另一条是换一个不依赖注意力的记忆基座。
  • 风险与边界（须明确）：全部为厂商自述，无第三方基准；社区质疑集中在常数因子——单次记忆访问需触及 9 个 cell 且每格涉及注意力计算，渐近复杂度虽是线性/常量，常数可能很大；真实大规模场景表现待独立验证。
关键指标 / 资源
  • 评测/性能：无公开基准分数，仅有「胜过注意力」的公司声明（自述数据，无第三方复现，待核实）；验证方式为「在 LLM 中直接构建 Python」的公司演示，非标准化评测
  • 资源：Percepta 官方博客两篇（Can LLMs Grow Their Own Capabilities；Spotlight），未公布论文编号与权重/代码可用性
  • 来源：AGI Hunt 汇总

5. 苹果收紧 macOS「完整磁盘访问」授权：因桌面 AI Agent 风险上升，要求「非常明确的用户操作」方可授予

第一来源：Apple 官方开发者博客 / Reuters ｜ 2026-10-02 美西 17:00 ≈ 北京 10-03 08:00
事件概述

苹果在面向开发者的博客中宣布将调整 macOS 权限机制，为「完整磁盘访问」（Full Disk Access）增加额外控制措施，规定真正需要该级别访问的应用必须通过更明确（very explicit）的用户操作才能完成授权。苹果给出的理由是：「随着 AI Agent 变得愈发自主且能力增强，此类访问带来的风险将实质性增长」。此举直接回应 Inc. 专栏作者 Jason Aten 对 Meta Muse 的指控——称 Muse 在其未授权的情况下读取了私人消息；Meta 发言人 Andy Stone 公开否认，称 Messages 访问严格 opt-in，须同时开启完整磁盘访问与 Messages 连接器。

技术与工程价值
  • 核心机制：macOS 与 iOS/iPad 的关键差异在于后者默认沙箱隔离、前者以高灵活性换取之——一旦授予完整磁盘访问，应用可触及文件、邮件、消息乃至浏览历史。苹果指出的要害是权限模型与 Agent 形态的错配：传统应用被动读取，而 Agent 会依据指令自主执行动作，风险的性质与量级都变了。
  • 实际影响：这是操作系统层首次因 AI Agent 而收紧既有权限授予机制，而非仅新增 Agent 权限——方向由「给 Agent 更多能力」转为「让高危授权更难发生」。对桌面 Agent 开发者的直接工程含义：Full Disk Access 将从「一次勾选」变成需要显式意图确认的关键路径，且叠加了此前 Wired 报道的 ChatGPT macOS 应用漏洞这一前置背景。但苹果未说明新控制的生效时间，且本次调整由一起未获独立证实的隐私争议触发。
  • 交叉参照：O 盘另一实例 10/3 00:32 版已收录 GitHub Copilot computer use（10/1 public preview），说明桌面 Agent 的能力扩张与权限收敛正在同一周内并行发生。
关键指标 / 资源
  • 关键事实：苹果 10/2（周五）美东发布官方开发者博客声明 + Reuters 同步报道；生效时间未公布（待核实）；Meta 与 Jason Aten 各执一词，争议未经独立取证（待核实）
